# 行业解决方案章节模板与检查清单

一芥智能研究院｜2026年10月18日｜以[工程机械章节](../中册-行业解决方案/C01-工程机械.md)为结构参照

中册帮助企业认识行业数字化方案的总体关系、应用模块与业务价值，再判断智力服务能增加什么。所有行业章采用五节正文，章末独立列“参考资料”。企业现状诊断、目标确认、蓝图、计划、建设组织及项目验收的共用方法统一见[上册第八章](../上册-研究报告/08-实施建议-从改造机会到可验证行动.md)。

每篇围绕明确的经营对象、专业流程与责任交付展开。住宿与餐饮、种植与林牧渔、药品与医疗装备、批发与零售等，业务架构和主要模块不同，应分别成篇；一份上位行业指南可以按其明确范围支撑多篇，图示与案例归到实际适用行业。工程机械整机与配套、汽车与零部件等同一产业链的角色关系，可以在同章分流，说明各类企业选读哪些模块。行业边界及当前覆盖范围见[分篇说明](../索引/中册行业分篇说明.md)。

## 第一节　行业特点、适用企业与业务目标

写清服务的客户、企业类型、产业链位置、产品或服务的交付方式，以及决定经营结果的专业条件。多种细分企业共用一章时，说明哪些模块分别适用，避免把整机厂、零部件厂和服务单位，或不同服务机构写成相同业务。

标题与适用范围对应本章实际展开的模块。资料仅支持某类作业、产品或局部服务时明确限定；目录列举、共用政策与单个案例不足以证明已经形成全部细分行业方案。需补专业资料的方向在覆盖范围中另列，不能用改行业名的相同正文凑成独立篇目。

目标落到产品、质量、交付、资源使用、服务兑现和经营判断。企业规模、系统数量、Excel使用与否不能代替实际能力判断，参考资料中的行业观察保留其时间与范围。

## 第二节　行业数字化方案的总体架构

先给出主要参考文件及适用范围，再解释架构怎样组织业务和技术：产业链或业务主线是什么，各层及模块承担什么，设备、软件、数据、模型、人员与外部伙伴怎样相互连接。原图配合完整说明，读者应能据此理解整套方案的作用。

- 正式指南提供总体架构时，保留其层次、名称和主要关系；多份资料分别承担架构、专业模块或案例依据时，说明各自用途。
- 来源是政策任务、研究框架或企业案例时，按其实际性质表述。将来源要点组织为业务模块，明确哪些关系是本报告的应用整理，不能将其称为文件已经发布的完整行业架构。
- 有明确源图时，图片直接嵌入正文，并可点击查看原尺寸，不能只留下跳转PDF的链接。已有图题、场景名称、编号、版本与公开链接保留；相邻图注注明PDF文件页码，原文另有印刷页码时同时列出，并链接具体源页。裁切仅去除页面外围留白，保留图内文字、连线、图例、图题、来源、必要脚注及水印；来源登记沿用[图示来源记录](../中册-行业解决方案/assets/README.md)。
- 来源列有联网、优化算法、仿真、机器视觉、预测维护或自动控制时，按其功能与条件完整解释。这些是行业方案提供的参考能力，具体企业是否建成需另行核实。

## 第三节　主要数字化模块、建设内容与业务价值

这是行业方案的主要篇幅。按行业参考文件的实际覆盖展开重要模块，不只选择容易增加AI的几个任务。模块数量由业务与资料决定，篇幅应足以让读者独立理解数字化方案本身的价值。

每个模块围绕连贯的业务说明展开，通常需要回答下列问题，不把表中各项机械复制成一套小标题：

| 讲解内容 | 应回答的问题 |
| --- | --- |
| 业务与产物 | 谁处理什么对象，输入来自哪里，形成什么，交给谁使用？ |
| 主要功能 | 系统、设备与专业工具怎样记录、设计、计算、仿真、监测、分析、执行或控制？ |
| 建设条件 | 需要什么软件、设备、接口、数据、规则、专业模型、知识与人员条件？ |
| 模块关系 | 同一对象、版本、状态、质量要求或资源条件怎样进入上下游？ |
| 独立价值 | 对质量、交付、效率、资源、服务或经营判断有什么具体作用，何种条件影响实际使用？ |

专业工艺、控制、检测、临床、教学、金融或公共服务的特定要求放在相应模块解释。可以说明模块可用性的判断依据，避免重新展开项目计划、通用职责分工、整章预算或统一验收流程。

本节说明参考方案怎样形成能力。描述具体企业已建系统、实际使用与效果时，引用相应案例，并保留原始来源、使用阶段与适用范围。

## 第四节　在数字化基础上增加智力服务

逐项对应前面的模块，说明服务怎样改变具体工作。先交代当前资料和工具承担什么，再写新增服务取得哪些依据、做什么、交出什么、由谁采用，以及可能减少哪种工作或等待。

| 新增作用 | 需要具体说明的工作 | 价值如何体现 |
| --- | --- | --- |
| 协助建造 | 需求与规则整理、数据检查、工具开发、接口适配、测试及交付资料准备。 | 在专业质量与实际可用的条件下，降低部分开发、试验和修改投入，让较小需求更容易得到工具支持。 |
| 理解与协调 | 理解不同表达，关联对象与版本，整理变更背景、缺项及下一步处理。 | 减少查找、转述与重复核对，缩短跨模块信息更新和接手等待。 |
| 分析与推理 | 汇集获准证据、调用专业工具、比较情况、提出原因假设与备选动作，跟踪获准处理。 | 使分析更及时、覆盖更多日常问题，并在条件成立时持续承接任务。 |

按实际任务选用这些作用，不要求每个模块凑齐三类服务。低成本、快响应、可持续运行需要落到具体变化；专业计算、固定规则、工业AI及企业已建能力的贡献保持原有归属。建设时使用服务与运行时调用服务分别表达，已有系统企业与基础薄弱企业的进入方式按实际条件说明。

本节可以写专业人员的确认与后续采用，但不再设置建设蓝图、实施计划、通用五类职责、整章投入验收或扩展停止等独立内容。新增价值保留适用条件，不填统一降本比例。

## 第五节　适用结论

用少量段落收束适用企业、主要模块、数字化方案本身的价值与服务新增机会。指出已有基础的企业怎样复用与补强，基础薄弱企业怎样借助新的建造与运行方式形成能力。效果由实际使用、业务结果和完整投入检验。

不在结论恢复已删除的实施篇，也不另设“企业参照”栏目。企业案例在支撑的模块或服务应用处就近出现，完整过程在下册维护。

## 参考资料格式

行业章末使用不带节号的二级标题`参考资料`，从[1]开始连续编号，各条独立成段，一条登记一份独立资料或案例。采用上册格式：

“[序号] 发布或编制机构／作者．资料完整题名（附公开原文链接）．出版或发布年份，PDF物理页／印刷页／HTML章节。引用范围：本章使用的架构、图表、模块或事实。”

示例：

[1] 工业和信息化部办公厅．[工业互联网与工程机械行业融合应用参考指南（2023年）](https://www.gov.cn/zhengce/zhengceku/202311/P020231118422003936163.pdf)．2023，PDF第54—68页。引用范围：总体架构、车间—企业—产业实施架构与网络建设；图3-2见PDF第57页、印刷第51页。资料库编号B02。

参考资料直接登记外部原始出处，沿用其明确作者、发布账号或机构，注明正文所引场景、使用阶段、页码或时间点及来源性质；确无署名的材料写为“佚名”。本报告及下册案例不作为参考文献条目，正文需要指引时使用案例名和普通内部链接。数字化、网络化、智能化等概念有外部依据时，引用相应研究或政策原文，并保留适用范围；智力服务的具体任务安排和验收设计按本报告建议表达。资料题名中的年份与实际出版年份分别保留，例如题名含2025年而封面为2026年3月的报告按2026年出版登记。

参考条目覆盖正文实际使用的主要文件和案例依据。保留图题与正文就近的页码链接，章末统一书目不能代替具体定位；转引材料注明通过哪份资料引用，未经直接研读不写成直接引用。方案建议与来源事实的界限在必要位置简明说明，不用反复出现的编写过程说明打断业务叙述。

## 交付检查

1. 是否保留五节正文与独立参考资料，且没有重复的实施篇？
2. 是否充分解释行业总体关系和数字化模块，第三节具有独立阅读价值？
3. 智力服务是否对应模块，说明新增动作、输入、工具、产物、采用及价值条件？
4. 是否区分行业参考能力、企业实际已建能力、基础补建与服务增量？
5. 是否保留专业模型、工业AI和规则程序的贡献，没有全部归于新增服务？
6. 图示是否直接显示并可放大，文字、连线、图题与来源是否完整，PDF及印刷页码能否回查；模块名称、场景编号、案例事实及使用阶段是否准确？
7. 参考资料是否直接指向外部原始出处，机构、题名、年份、页码、链接和引用范围是否完整，编号是否连续；本书内部导航是否使用普通链接？
8. 是否清除“原方案、原模块、原功能”等模糊指代和面向读者的编写过程口吻？
