# 企业案例写作模板与检查清单

[编写约定](../CONTRIBUTING.md) · [三篇模板样稿](../草稿箱/案例改写试稿-三篇对照.md)

每篇案例按“企业是谁—开展什么业务—遇到什么问题—怎样解决—取得什么效果”展开。一级标题是案例编号与题名；下列七个二级标题的名称、编号和顺序固定。篇幅可以不同，各节只呈现来源支持的内容。

## 固定标题与每节必写内容

| 层级与标题 | 必写内容 | 检查时追问 |
| --- | --- | --- |
| 一级：编号＋案例题名 | 沿用正式案例的编号与题名，每篇只设一个一级标题 | 能否与来源索引中的同一主体对应？ |
| 二级：1. 企业介绍 | 主体身份、主营业务和经营方式；服务商案例区分供方与客户 | 谁在改造，谁在使用，谁提供资料？ |
| 二级：2. 业务背景与改造目标 | 本次涉及的业务、相关岗位或部门、为什么开展改造、希望改善什么 | 目标是企业明确提出的，还是编者概括？ |
| 二级：3. 面临的问题 | 原来怎样做，哪里受阻，以及对业务结果的影响 | 具体是哪个环节，缺了什么，影响谁？ |
| 二级：4. 解决方案与实施过程 | 实际采取的措施、尝试与调整，AI、程序和人的工作及交接 | 谁提供输入、执行、检查、承接和处理异常？哪些已经实施？ |
| 二级：5. 实施效果 | 按阶段呈现实际变化，与改造目标及问题对应；有量化结果时交代数字范围 | 是试点、局部使用还是设想？数字比较了什么？ |
| 二级：6. 分析与启示 | 明示“一芥分析”，解释可借鉴的机制、适用条件和后续检验办法 | 分析是否由前文事实支持，是否新增了企业事实？ |
| 二级：7. 资料来源 | 来源性质、公开链接、发布时间（可查时）、页码或时间点；各场景阶段与范围 | 是否能回到具体材料？自述与独立核验是否区分？ |

表中问题用于指导检索和审读，不要求每个字段都有描述。发现资料不足时，先回查原始来源并搜索可访问的公开资料；核实后补入正文，仍没有可靠依据的描述直接省略。例如，找不到验收人的资料，就不写验收职责，不能凭一般业务经验补成企业已经实行的流程。

正文不列“待补资料”等编辑任务，也不逐项罗列缺失字段。必要的来源归属、实际阶段和数字口径仍写清；检索记录留在内部工作记录中。

## 可复制的案例骨架

以下是正式案例文件的标题结构。花括号内是写作提示，使用时替换为有依据的正文。

```markdown
# {编号} {案例题名}

## 1. 企业介绍

{主体是谁、主营业务是什么；区分服务商与客户。}

## 2. 业务背景与改造目标

{本次业务及参与岗位，开展改造的原因和目标。}

## 3. 面临的问题

{原有做法、具体受阻环节及其业务影响。}

## 4. 解决方案与实施过程

{实际措施与实施过程，AI、程序和人的职责及交接。}

## 5. 实施效果

{实际阶段与有依据的变化；有量化结果时写清数字口径。}

## 6. 分析与启示

**一芥分析：**{机制、适用条件及后续检验。}

## 7. 资料来源

{来源性质、链接、发布时间或研究日期、页码或时间定位。}
```

## 三级标题、阶段与缺项的写法

三级标题按内容需要设置，不增加新的二级标题。多场景案例在第3、4、5节使用同名、同序的三级标题，例如迪欧家具的“问答与考核—设计资料共享—售后联动”，让问题、措施和效果逐项对应。单一场景可以直接写连续段落，较长的实施过程可以按实际步骤分设三级标题。

早期试点、当前使用和后续计划分别说明。只有设想的场景，第4节写提出的方案与尚未实施的环节，第5节说明尚无实施结果，不能填入预计收益。同一企业的多项应用也不能拼写成已经运行的完整系统。

匿名案例只介绍能够确认的主体与业务，不猜测企业身份。方法、原型和演示案例在第1节介绍项目或方法及提出者。没有量化效果时，第5节呈现有依据的定性变化；只有设想时，说明方案所处阶段。保持七节结构，不用空标题或缺项清单填充正文。

正式改写保留原编号、题名和场景锚点。每个原锚点只出现一次，放在仍能支持原引用的相关段落前；相应场景标明原有阶段，叙述保持来源索引所支持的范围。索引中的研究说明不要求逐字放进正文。事实更新时，按编写约定同步来源索引及相关引用。

## 逐篇内容检查清单

- [ ] 第1节说明了有依据的主体、业务及供需双方；匿名主体没有被猜测补全。
- [ ] 第2节写清本次业务与目标；编者推断没有写成企业自述。
- [ ] 第3节写清原有做法和具体问题，而不是只列“效率低”等概括。
- [ ] 第4节解释有依据的具体改变和分工；输入、验收、异常或交接安排没有用通用流程补写。
- [ ] 第5节与问题及目标对应；计划、局部使用与早期结果分别呈现；量化结果只采用口径可说明的数据，否则保留有依据的定性描述。
- [ ] 多场景的第3、4、5节同名、同序；没有把不同阶段合成统一效果。
- [ ] 第6节标明分析，结论由现有材料支持；适用条件与待验证判断写清。
- [ ] 第7节可定位原始材料，说明自述、演示或独立核验的性质；日期有可靠依据时写入。
- [ ] 原编号、场景锚点及阶段范围保留，相关引用仍能得到对应段落支持。
- [ ] 缺失信息已先回查来源或检索，未核实的描述已省略；正文没有资料补充任务、缺项清单、未替换提示或空节。

## 自动检查与使用范围

从仓库根目录运行：

```bash
python3 scripts/check-case-structure.py 草稿箱/案例改写样稿
python3 scripts/check-case-structure.py 下册-案例汇编
python3 scripts/validate.py
```

[结构检查脚本](../scripts/check-case-structure.py)依据[标题配置](case-structure.json)，检查唯一一级标题、编号题名、七节名称与顺序、空节、占位符、多个三级场景标题的对应关系，以及已有场景锚点和阶段是否保留；正文中的资料补充任务直接报错。它也接受单篇文件或案例目录。全库校验同时检查全部正式案例的固定结构。

**结构通过不代表内容完整或事实已经核验。** 正文质量、场景语义和来源支持仍按上述清单逐项审读；后续新增或改写案例继续运行结构检查与全库校验。
