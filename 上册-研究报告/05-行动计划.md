<a id="section-5-1"></a>
## 5.1 从方向倒推改造蓝图

蓝图可以先回答四层问题：**目标客户为什么选择我们；企业需要提供什么业务与能力；这些业务经过哪些工作流；工作流中又有哪些任务、判断和交接。**

比如，一家定制制造企业希望提高询价响应，同时守住利润。蓝图就要把图纸理解、工艺、物料、成本、报价与客户沟通连起来。若只从"AI能看图纸"进入，很容易跳过决定报价可靠性的企业条件。[C02 非标制造企业AI报价][C02]正好展示了从直接出价退回分段协作的过程。

方向还会改变推进顺序。[C04 压力容器企业成本核算需求梳理][C04]的需求讨论中，客户要求财务、采购和仓库提前，因为实际成本算不清，下一轮报价就缺乏依据。发生的是需求与排期调整，成本系统尚未交付——但它已经说明，**实施不必机械沿着软件模块的次序推进**。

一张可讨论的蓝图，可以把现状、目标与依赖放在一起。

| 层次 | 需要写清的内容 |
| --- | --- |
| 客户与经营目标 | 服务谁，改善哪种客户交付，保留什么选择理由 |
| 业务与职能 | 哪些工作直接支撑目标，哪些责任不能缺位 |
| 工作流 | 输入到最终使用经过哪些环节，在哪里判断与等待 |
| 具体任务 | 输入、产物、执行者、交接者与验收条件 |
| 改造依赖 | 哪些数据、系统、标准与人员条件尚未具备 |
| 基线与预期 | 当前怎样完成，希望改变什么，如何验证 |

这张蓝图不用一开始做到完备，但应足以发现关系：改一个环节会影响谁，某个目标是否需要先补资料，某项工具是否只解决了表面问题。随后再用四象限筛选任务，边界才有业务依据。

<a id="section-5-2"></a>
## 5.2 用四象限确定边界

四象限放入的是蓝图中的具体任务。**纵向**判断这段工作是否应该交给AI参与改造，依据客户价值与企业取舍；**横向**判断当前能否做好，依据真实输入、质量要求、工具条件和实测结果。

"应该做"与"能够做"要分别回答。工具能生成某种产物，不代表企业值得持续投入；一个任务很有价值，也不代表当前已经能够可靠承接。

| 业务判断／当前能力 | 当前能够做好 | 当前尚不能可靠做好 |
| --- | --- | --- |
| 应该交给AI参与改造 | **优先候选**：继续检查下游、责任与总投入 | **准备与观察**：补依据，保留人工承接，小范围验证 |
| 当前不应交给AI | **保留现有机制**：即使技术可做，也服从业务取舍 | **暂不投入**：记录判断，条件变化后再复核 |

"尚不能"也包括证据不足。**没有真实测试的能力，不宜直接归入可靠可做**；可以先用受控任务取得证据，再调整位置。第二章的三条判据在这里可以直接使用：能否说明、能否验收、协调成本是否低于执行成本。

客户直接沟通与沟通准备应当拆开。本报告采用的人主导、AI辅助取向，意味着**关系、承诺和重要判断由人承担**；资料搜集、记录整理与会前准备，则可以按价值和能力另行评估。第三方案例存在不同安排，应如实记录其范围，不能把一种做法视为普遍规则。

进入优先候选以后，还要排次序。**经营价值高、负责人明确、验收可做、前置条件较齐、下游能够接住**的范围，通常更适合先验证。若关键资料尚未取得，可以先建设必要条件，或选择另一个能验证的任务。

[I04 运动门店SaaS企业AI应用][I04]讨论过录音工牌却最终未做，提供了"能采集不等于值得采集"的实际取舍。**客户信任和员工接受影响的是业务价值，不能只放在技术开发完成之后处理。**

横向的"当前能够做好"要依据实测，而不是依据演示。[I03 语音AI服务商内部应用与产品演示][I03]在演示中上传课程知识、设置客服形象，并接听了一通带噪声的咨询电话，把后续方案交给顾问。但**实际客户运行中的解决率、误答和转人工情况，没有在这通电话中得到检验**；材料中的"成本下降九成、低单价摊销"也缺完整分母与服务范围。这正好说明四象限的横向判断为什么要用受控任务取证据：**演示能证明"搭得起来"，不能证明"稳定可做"。**

<a id="section-5-3"></a>
## 5.3 从局部运行到逐步扩展

局部运行要选**能够看清输入、交付和责任的范围**。先确认一次任务可以完成，再检查跨岗位接手，之后在验证过的条件内引入定时或事件触发。**每次扩展都要说明新增了什么工作与责任。**

[F10 上海消费品门店AI对账][F10]把试点控制在个位数门店，便于观察首轮核对和人工追差；[C11 澳洲乳企海外动销分析][C11]先跑中国一条产品线，要求数字能追源、结论能进周会，再接越南。这些过程提供的是**有边界的扩展方式**，不能外推为全网或全球已经完成。

局部试验应保留原有基线。新旧结果完成程度不同，就先说明差别，不急于计算节省比例。

工具做出来以后，还要留出改进与停止的空间。[F09 3C外贸企业AI自建业务系统][F09]曾花30天尝试大系统却未达预期，后来把"同事能用、经常能用"作为落地要求。[I04][I04]已有报表但调用很少，也提醒企业**按真实采用复核投入**。

第三章的四种瓶颈形态在这里可以直接用作检查表：核验内容是否改变、瓶颈是否已从审核转移到行动、能否把核验前移、指标口径是否与交付口径一致。

<a id="section-5-4"></a>
## 5.4 三项环境怎样随试点生长

第四章说明，主动触发需要共同约定、能力网络与知识网络三项环境。本节说明它们**怎样长出来**——不是先建平台，而是按实际遇到的问题逐个补。

| 试点中反复出现的问题 | 要补的环境 |
| --- | --- |
| 同一字段反复解释 | 共同约定：把已确认的口径写下来 |
| 经常找不到可用工具 | 能力目录：登记能力、适用范围与承接条件 |
| 依据散在不同设备与记录里 | 知识发现机制：资源注册、统一索引与访问范围 |
| 触发之后没人接 | 承接者与异常出口：指定责任人并约定返回路径 |

这个顺序有一个重要含义：**三项环境是试点运行的副产品，不是前置的基建工程。** 先建一整套平台再找人使用，是 F08 记录过的失败方式——第一年建成的知识库、模型与Agent员工，最后没有真正用起来。

各环境的登记内容，第四章已分别给出（共同约定的六项、能力登记表、知识网络三层结构）。本节只强调两条操作原则：

**一、约定要短。** 企业可以先为一条试点流程建立简短说明，随着使用补齐例外。不必把全部操作写成庞大手册，但**重要边界不能只存在于某个人的记忆里**。

**二、目录要带范围。** 能力登记中的"可以做"必须带适用条件。不能因为某个演示成功，就让它接收所有同名任务——这是第四章在能力网络处给出的判断。

<a id="section-5-5"></a>
## 5.5 记录与验收：一次试验要留下什么

一次试验要留下什么，取决于它要支撑哪一层的判断。第二章到第四章给出了三层回收，对应三种验收口径。

| 层级 | 验收口径 | 主要看什么 |
| --- | --- | --- |
| 单点 | 同一质量要求下，达到验收标准的任务总投入是否下降 | 准备、执行、核验、返工、维护与服务费用 |
| 流程 | 沿着同一业务对象走完全程，周期、等待与返工总量是否下降 | 交接是否中断，省下的劳动是否转移给别人 |
| 组织 | 有效投入的产出是否可辨认，无效投入是否被停止 | 采用情况，以及不被使用的生成有哪些 |

对应到一次具体试验，需要记录的内容如下。

| 一次试验的记录 | 用来作出的决定 |
| --- | --- |
| 原来的任务、质量和投入 | 确认比较对象一致 |
| 新安排与负责人 | 确认改变发生在哪里 |
| 采用及放弃原因 | 判断实际工作是否愿意使用 |
| 合格交付、等待与返工 | 判断下游是否获得改善 |
| 人工介入、维护与费用 | 判断收益是否覆盖投入 |
| 业务结果与未验证事项 | 决定继续、调整、扩展或停止 |

这份表的前两行决定这次试验有没有意义，后四行决定它能不能被推广。**"新安排与负责人"必须填实**——第三章的四类断点中，有相当一部分直接来自这一格空缺。

记录也有边界。[F11 温州连锁烘焙企业AI经营管理][F11]的促销调整按七天标准观察，得到了销量下降、总毛利额上升的结果；这是**有边界的一次业务试验，尚无净利润和长期持续改善数据**。试验记录的价值在于说明走到了哪一步，而不是替代长期结论。

<a id="section-5-6"></a>
## 5.6 什么必须由人判断，何时减少或停止

第二章的四类工作中，"专业判断与对外承诺"通常不是被拆掉的部分，而是任务拆分的边界。本节把边界写成可执行的判断。

**必须由人判断的，至少包括四类：**

1. **对外承诺**——报价、合同、医疗与法律意见、对客户的交付承诺。M03 的一键出图之所以被改为可调参初稿，正是因为参数关系专业责任。
2. **异常与例外**——工具处理不了的情况。S01 的做法是"正常业务继续流转，异常交人处理"；这条分工必须在事前写明。
3. **标准与尺度的确立**——什么叫异常、什么算合格、采用哪种审核尺度。这些不能由工具自己决定。
4. **价值取舍**——哪些任务值得做、哪些资源投向哪里、何时停止。

**减少或停止的条件，同样需要事前写明。** 从材料中至少可以提取四条：

- **采用不足**：工具已具备而无人使用。I04 的报表两年前就有、后台调用寥寥；R01 培训后一周员工就不再使用。
- **核验吃掉收益**：上游省下的时间被下游核验抵消。I01 早期约八成图仍需PS补救，比真人拍摄更贵。
- **前提不成立**：外部条件使方案无法落地。M02 因监管系统不能开放接口而叫停采购。
- **口径无法核对**：没有基线、没有对照、没有完整成本清单。F04 的节约数字在缺少完整成本清单时无法作为财务确认。

这四条的共同点是：**它们都可以在事前被定义为"停止条件"，而不必等到事后来争论。** 在蓝图（5.1）里写"基线与预期"，在试验记录（5.5）里写"业务结果与未验证事项"，就是把停止条件提前确定。

<a id="section-5-7"></a>
## 5.7 用一次跨来源任务验收知识网络

三项环境中最难验证的是知识网络，因为它没有单一产物。可以用一项跨来源任务来验收。

**任务选择：一次产品改进。** 手机上收录过相关文章，桌面有相关播客与视频，项目里有PRD和Bug，历史会话保留了为什么没有采用某方案。任务是把这些来源组织到一起，形成能够追溯的建议，再由负责人决定是否采纳。

这条任务之所以适合验收，是因为它同时触发三项环境：需要**共同约定**说明"什么算有效依据"，需要**能力网络**找到能读取各类来源的承接者，需要**知识网络**保证取回的是正确版本。

验收维度有五个：

1. 是否找到相关依据；
2. 是否读到了正确版本；
3. 访问范围是否恰当；
4. 缺失是否明确；
5. 建议是否减少了重复解释和引用过时结论。

第三个维度容易被忽略。[F01 面向东南亚的服装跨境电商业务协同][F01]的情形是：交付之后客户移除权限，后续营收、广告成本与利润没有完整跟踪。**访问范围不只是安全设置，它决定了知识能不能在需要的时候被用上。**

知识网络的价值最后还要回到任务：**它是否实际帮助下一次工作更可靠地完成。** 企业可以先从一个值得改造、能够验收的范围开始，在运行中形成共同约定、连接能力、积累有效知识，再按结果逐步扩展。

<a id="section-5-8"></a>
## 5.8 事实边界

本章与前三章的性质不同：**前三章在判断已经发生了什么，本章在提出应该怎么做。** 因此需要逐项说明它们各自的依据强度。

| 本章的哪一部分 | 依据 | 强度 |
| --- | --- | --- |
| 从方向倒推蓝图（5.1） | C02 的直接出价失败、C04 的需求排期调整 | **有案例支持**，但只有两条 |
| 四象限确定边界（5.2） | I04 的录音工牌未实施；第二章三条判据 | **有案例支持**；四象限本身是本报告提出的框架 |
| 局部运行到扩展（5.3） | F10 的个位数门店、C11 的单条产品线、F09 的30天未达预期 | **有案例支持**，属于"有边界的扩展方式" |
| 三项环境随试点生长（5.4） | F08 第一年建成的知识库与Agent员工没有被用起来 | **反例支持**：先建平台再找使用是失败路径 |
| 记录与验收（5.5） | F11 的七天观察；第二章到第四章的三层口径 | **口径来自正文**，三张记录表是本报告提出的工具 |
| 什么必须由人判断（5.6） | M03 的调参确认、S01 的异常交人、第二章的四类划分 | **有案例支持**；四条停止条件由材料归纳 |
| 知识网络验收（5.7） | F01 的权限移除；D 附录的建设细节 | **验收维度为本报告提出，尚无企业按此完整执行** |

**因此，本章不主张任何一条已经被验证**：这里给出的是实施顺序与检查表，不是已被执行过的方案。其中"三项环境随试点生长"有一条明确的反例支持（F08），这一点比其他各项更确定——**先建平台再找人使用，是材料里记录过的失败方式。**

还有两处需要标明为待验证：

- **5.4 的生长顺序**（共同约定 → 能力目录 → 知识发现）由问题驱动推出，没有企业按此顺序完整走过的记录；
- **5.5 的三层验收口径**中，组织层（有效投入的产出是否可辨认）目前没有企业级数据，第二章与第三章已分别说明。

本章的建议可以独立使用，但使用时应同时保留正文各章的阶段与口径标注——**建议本身没有阶段，被建议的对象才有。**
