# 第三章　LTC：从线索到回款

第二章交出销售能够继续跟进的有效线索。销售沿已有的客户事实、初步需要与未决项，继续核实购买条件，决定机会投入，再形成客户认可、企业能够兑现的承诺。合同签署以后，相关岗位还要完成履约、客户验收和约定收款，才能看清这笔业务取得了什么结果。

LTC（Lead to Cash，从线索到回款）将这些工作放在同一笔交易中考察。本章先解释商机推进、承诺、执行与收款中的问题，再提出共同组织工作的要求、数智化方案的建设交付物及其日常应用。方案是否有效，由客户承诺的实际兑现、资金结果与完整投入检验。

<a id="section-3-1"></a>
## 3.1 业务现状与问题：一笔业务怎样穿过多个部门

LTC从销售接住线索、核实机会开始，经过需求与方案确认、合同签署、履约及客户验收，追到约定款项实际收回、剩余责任明确接手。销售、方案、产品、商务、交付、供应、生产和财务按业务需要参与，同一人也可以兼任多个角色。华为2019年[网络安全立场文件的流程架构](https://www-file.huawei.com/-/media/corporate/pdf/public-policy/huaweis_position_paper_on_cybersecurity.pdf#page=34)并列列出MTL、IPD、LTC、ITR，2024年[ICT基础设施业务可持续发展报告](https://www-file.huawei.com/admin/asset/v1/pro/view/8a5be0e3b04643aaa297b0d1cf235e4f.pdf#page=9)将IPD、LTC、ITR列为主业务流程。本章借用其业务范围，具体环节和判断要求为本书整理。

销售取得线索材料以后，沿用客户已经说明的事实，继续了解希望改善的结果、采购安排、相关角色、期限和联系条件。邮件、客户管理系统及会议记录留下本次沟通，销售与方案负责人据此比较机会价值、适配难度和需要投入的支持，决定继续推进、培育或退出。

值得推进的机会进入需求与方案准备。销售和方案人员把客户需要转为可以核对的交付范围、配置及验收要求，产品、供应、交付和财务分别提供能力、物料、资源及成本依据。经过评审的方案与报价进入谈判，最终确认的范围、价格、交期、验收和付款条件随合同及附件保存，供后续岗位执行。

合同签署以后，交付负责人把承诺展开为订单、项目、批次与任务，核对物料、产能、现场配合和开工条件。采购、车间或项目人员从ERP、项目工具及相关单据取得本岗位需要的内容，财务接住付款节点与材料要求。一个商机可以形成多份合同，一份合同也可能分批交付、分期验收和付款。

履约过程中，各岗位留下物料到位、生产、实施及成果提交记录。新增要求、质量异常或延期需要核实对当前承诺的影响，取得相应决定，再进入执行。交付人员按有效合同与变更组织客户验收，分清内部完成、成果提交和客户实际接受的范围，并把证据交给财务及后续服务人员。

款项按合同约定的条件与节点处理，可能发生在开工前、履约中或验收后。财务、商务和交付核对条件、开票与实收，查明未到账和核销差异；收尾时列明剩余应收、质保及未决事项，由相应人员接手。交易中发现的客群误判返回MTL，产品能力差距进入IPD，客户持续问题进入ITR，原合同责任仍需继续跟踪。

在前端，企业可能反复准备商机材料，却始终没有明确的客户下一步；方案多次修改，仍在承诺前发现配置、成本或交期无法确认。合同已经签署，采购或交付却还在追问最终要求，使用的附件与销售确认的版本也可能不同。

进入履约后，系统报出的完成状态未必对应客户可接受的成果，变化已经批准却没有进入相关岗位安排。成果提交以后，还可能缺少验收材料，或者部分范围存在争议；财务看见应收，却难以判断款项卡在材料、验收、条款还是支付环节。项目报了结束，剩余义务和反复出现的问题也可能没有明确去向。

这些现象使一笔业务在多个岗位之间停顿。评价LTC，需要沿商机、合同、履约范围和款项的实际去向，确认客户承诺兑现到哪里、哪些条件尚未成立，再分析造成等待、返工及资金延后的原因。

<a id="section-3-2"></a>
## 3.2 原因分析：为什么签约、履约与回款没有顺利接续

前述问题分别出现在机会投入、承诺形成、合同执行、履约验收和资金收尾中。它们都可能使交易耗费更多资源，却需要回到不同的依据、交接和责任判断原因，不能只用签约数量、完成状态或未收款总额代替分析。

<a id="section-3-2-1"></a>
### 3.2.1 商机持续投入，为什么迟迟没有实质推进

客户有兴趣、提出问题或愿意看方案，并不直接说明购买条件已经成立。如果预算、期限、决策角色和采购安排主要来自销售推测，支持人员就难以知道本次准备会推动哪一步。商机在记录中持续活跃，专家、样机和方案投入却可能没有对应的客户行动。

机会之间的资源取舍也可能沿用旧判断。客户情况已经变化，推进依据没有更新；各请求分别说明自己的紧急程度，负责人看不到累计投入和未决条件。没有进展的机会于是反复取得支持，而真正需要及时处理的机会继续等待。查因要区分客户条件尚不明确、投入目的不清和内部支持受阻，不能把三者都归为销售跟进不足。

<a id="section-3-2-2"></a>
### 3.2.2 方案已经认可，为什么承诺仍难兑现

客户认可一项方案时，双方可能尚未对同一交付范围取得理解。客户说的使用效果，销售记录为功能名称，方案人员又按熟悉配置准备；适用条件、客户配合及验收办法没有确认，差异便会留到报价、实施或验收时才出现。

企业内部的依据还可能没有对应同一版本。产品能力已经更新，报价仍用旧配置；成本经过核算，现场条件、物料和资源却未确认；谈判又改变了原评审条件。局部判断各自成立，合在一起仍可能形成无法按约兑现的承诺。这类问题既涉及需求含义，也涉及专业约束与批准范围，需要对照当时确认的需求、配置、资源和最终说法辨认。

<a id="section-3-2-3"></a>
### 3.2.3 合同已经签署，为什么仍不能顺利开工

签署后的合同要进入订单、项目和岗位任务，才能成为执行输入。只按客户名称找材料，容易混入其他商机或合同；一份合同拆成多个批次以后，范围、数量和配置又可能没有逐项对应。采购收到的是谈判稿，交付拿到的计划缺少附件，都会使执行者继续追问或采用不适用的要求。

即使最终内容已经传到，开工还可能受到物料、产能、现场配合或约定付款条件限制。如果计划没有区分已确认条件与待补条件，系统分配了任务也不代表岗位能够开始。由此产生的等待，需要分清输入缺项、对象或版本错配，以及实际条件尚未具备；合同有了归属，工作未必已经接住。

<a id="section-3-2-4"></a>
### 3.2.4 进度不断更新，为什么延期与返工仍在发生

岗位报出的完成，可能指完成一道工序、提交一份文件或结束一次操作，下游需要的却是具备质量依据、能够继续使用的产物。记录久未更新、内部预检与客户接受混用，还会使负责人把尚待核实的状态当成已经具备的条件，影响后续安排。

履约也受到前后依赖和变更影响。物料延期、质量问题或客户增加要求以后，相关配置、任务和批次未必同时改变；批准记录与实际执行之间存在间隔，原计划仍继续使用。单个岗位提速因而可能伴随后续返工。分析时需要沿受影响交付项查明事实、依赖和变化的采用情况，区分进度信息失真、实际容量不足与变更未生效。

<a id="section-3-2-5"></a>
### 3.2.5 成果已经提交，为什么验收与回款仍被拖住

成果提交以后，客户还要按约确认范围与质量。实际成果不合要求、约定没有说清，或缺少测试与服务记录，都可能造成验收停顿。分批交付时，一部分已接受、另一部分待整改，如果只保留一个“完成”状态，财务也难以知道哪些付款条件已经成立。

未收款还可能发生在不同位置：材料没有齐备，条款或验收存在争议，客户未按约支付，或者已经到账但没有对应核销。应收、开票、付款承诺和实际到账混在一起，会掩盖这些差异，重复催问也无法消除真正的阻碍。需要沿具体付款节点与对应履约证据分辨原因，才能解释为何成果、应收和实收没有同步。

<a id="section-3-2-6"></a>
### 3.2.6 交易已经收尾，为什么责任与同类问题仍未结束

收款或报结项以后，仍可能存在剩余应收、质保、未决争议和客户问题。如果没有说明对应范围、当前状态及后续接收者，原负责人以为已经交清，新岗位又缺少背景，责任便容易停在两边之间。需要继续使用的资料和系统连接，也可能失去维护与访问安排。

偏差被写进复盘，也不代表后续做法发生变化。机会判断、报价规则、合同附件或交付方法的修订没有进入实际使用，下一笔业务就仍沿旧依据开展。一次交易的问题由此延续到下一轮投入，查因既要看剩余事项是否实际接手，也要看过去确认的修改后来用到了哪里。

这些原因沿同一交易相互影响。前端判断关系到资源和承诺，合同与执行关系到交付，验收与付款条件又影响资金结果；交易结束后的责任和反馈继续影响下一轮工作。整体方案需要把这些关系一起组织起来。

<a id="section-3-3"></a>
## 3.3 整体思路：围绕客户承诺贯通履约与回款

LTC的整体改进，以可兑现的合同、合格履约和按约回款为共同结果。沿同一笔交易组织事实、决定、执行与接手，再把这些要求落实为可交付、可运行的数智化方案。

<a id="section-3-3-1"></a>
### 3.3.1 围绕完整交易组织业务

机会投入和客户承诺需要同时考虑兑现条件。销售说明购买依据，产品、方案、供应、交付和财务核对能力、资源、成本及付款安排，有权人决定机会取舍与可承诺范围。华为[2012年报](https://www.huawei.com/-/media/corp2020/annual-report/pdf/2012-cn-hw_u_256091.pdf#page=94)把线索到回款与项目组织、资源分配共同讨论，[公司治理说明](https://www.huawei.com/cn/corporate-governance)提出流程责任人、关键控制点和职责分离，本章据此落实共同参与和关键决定的责任。

共同要求形成以后，让每个接收岗位取得可执行的输入。客户事实、适用规则、批准理由、有效版本、当前状态和接手责任沿交易关联并持续更新，形成各岗位接续使用的组织上下文。商机、合同、订单或项目、交付批次及款项保留实际关系，接收者能找到本次所需范围和依据；缺项与冲突返回能够解决的人。

承诺还要与实际承接能力配合。交期、物料、专业支持、现场和资金条件进入同一计划，采购、车间、交付及财务确认各自能否继续。批准变化以后，复查受影响的配置、任务、验收和付款节点，让决定进入实际执行；内部完成、客户接受和到账分别确认。

流程负责人沿完整履约和资金结果协调受阻工作，各专业保留相应判断与授权。剩余义务交给明确接收者，偏差返回市场、产品和服务工作；确认有效的修订进入后续方案、规则和安排，再由下一批交易检验。业务组织由此同时照顾本次兑现与持续改进。

<a id="section-3-3-2"></a>
### 3.3.2 数智化方案的建设内容与交付物

围绕这些要求，企业需要取得能够支持交易推进和兑现的建设成果。以下七类按本轮范围与既有基础配置，说明各项成果覆盖哪些交易、岗位与操作，哪些功能已经验证可用，以及由谁持续维护。

**业务与数据标准包。** 交付经确认的LTC流程、机会评估和承诺评审要求、关键控制点及责任分工，配套数据字典、状态定义和指标口径。商机、需求、配置、合同、订单或项目、批次、验收及款项分别建立标识，明确关联范围、数量金额口径与维护人。内部完成、成果提交、客户接受、应收、开票和实收分别定义，提供分批交付、分期付款及变更的样本，使各岗位能够按同一依据记录和核对。

**LTC数据仓库。** 在现有或新建平台中，交付交易主题的数据表、关联模型、来源映射、接入更新任务和整理后的首批数据。连接机会投入、合同及变更、履约实绩、验收、应收与实收，支持从一笔款项回查交付条件，也能从一个商机追到多份合同和各批次结果。配套币种、范围和时间口径、质量检查及查询权限；业务状态由相应系统维护，仓库按约定更新，保留缺项及来源。

**交易与履约知识库。** 交付有效产品条件、配置与核价依据、经批准的交易规则、交付规范、验收样例及历史复盘，配套检索、引用、版本和维护功能。各岗位及获准服务能够取得本次适用的规则，回查原文与批准范围。客户确认、批准方案和最终附件与相应交易关联，变化后能定位受影响的使用位置。

**场景应用与经营看板。** 交付商机核实、方案评审、合同交接、履约变更、验收、回款及收尾等岗位页面、表单和查询功能，说明可完成的操作及结果去向。看板呈现机会投入、承诺变化、交付与验收、到期应收与实收、等待和未决事项，并能回查具体合同、批次及款项。岗位视图配套可见字段、修改权限和接收要求，按真实业务样本验证，支持负责人协调完整交易。

**智能体与自动工作流。** 交付已配置的客户背景整理、需求与合同比对、报价准备、履约异常分析、验收材料检查或回款差异追查任务，明确输入、输出、可用资料与工具、权限及人工确认节点。工作流连接资料新增、承诺批准、变更、退回和付款节点等条件，组织查询、任务分发、系统操作、状态回写及异常接手。配置版本、测试样例和执行记录随同交付，使获准任务能够重复调用并核对结果。

**数据接口与系统集成。** 交付连接客户管理、产品资料、ERP、项目、审批和财务工具的接口或适配程序，配套交易及字段映射、读写权限、同步和联调配置。最终合同与批准结果进入订单和计划，履约与验收记录进入相应付款节点，到账与核销结果返回本次交易。联调覆盖传递失败、重复处理和更正路径，明确各项记录由谁维护、哪个系统负责确认，以及连接变更后的处理责任。

**验收与运维移交包。** 对建成部分交付部署与配置文件、约定范围内的源码或导出配置、接口及操作维护说明，以及测试和试运行记录。样本覆盖分批交付、分期付款、变更、更正及失败处理，使用者能够取得资料、完成交接并确认结果，维护者能够更新依据、检查执行和处理故障。账号权限、持续费用、运行依赖和交付后的维护责任同时移交。

咨询阶段形成经确认的业务标准、交易关系模型、数据来源映射、应用原型、任务规格、接口设计与验收清单；建设阶段按清单交付已接入的数据、可操作应用、可调用服务、已联调接口及可执行工作流。标准约束记录和判断，数据与知识提供依据，应用承接岗位操作，接口与工作流连接前后执行，看板支持协调和复核，共同构成LTC的端到端数智化方案。

<a id="section-3-3-3"></a>
### 3.3.3 三化与智力服务的作用

数字化使需求、承诺、履约和款项能够按交易及范围记录、查询与计算。智力服务可以协助建设资料抽取、配置核对和查询工具，也可以在运行中整理沟通、合同与成果记录，提出差异和缺项。明确的数量、金额与企业核价规则交程序处理，专业人员确认事实和例外，使数字资料能够支持实际报价、排产与收款核对。

网络化让商机、合同、订单或项目、批次与款项在系统和岗位之间接续。服务可以协助开发适配工具、整理字段与业务关系，也可以为销售、交付和财务准备各自需要的背景，解释说法差异并提示冲突。程序按规则传递决定与状态，接收者确认所需输入已经可用；变更沿对应范围进入采购、履约、验收和财务工作。

智能化利用这些依据比较机会、核对承诺与实绩，分析延期、返工和未收款的可能原因。服务可以准备补料、调整顺序、分批交付或补齐证据的选项，说明依据和约束，再执行获准的查找、材料准备与跟踪任务。专业人员核实重要事实，有权者决定客户条件及资源取舍，后续用新的履约证据和到账结果检验原判断。

在适合且经过验证的任务中，较低的建设和处理投入可以扩大资料检查与背景准备的覆盖，快速响应可以缩短变化出现到相关岗位取得可用材料的间隔。资料更新、进度核对和异常准备等任务可以7×24小时持续运行，使长期交易中的变化更及时进入处理。三项能力围绕同一受阻工作并行建设，投入和作用仍按实际运行检验。

<a id="section-3-3-4"></a>
### 3.3.4 人、程序与智力服务的配合

人机配合同时落实到关键决定与日常任务。人员确认购买事实、需求与专业质量，有权者决定报价、交期、合同及付款条件；程序承担明确的计算、传递和状态记录，智力服务承担需要理解上下文的整理、比较与分析。使用者验证工具，维护者管理有效依据及运行，权限不足、状态不明和任务失败交约定人员接手。

例如客户增加安装要求，程序把变化关联到本次商机和合同，服务比较对配置、现场、工期、验收及付款条件的影响，准备待确认事项。销售与相应专业人员核实，有权人批准后，程序与服务按授权更新相关计划、准备交接，接收岗位确认采用。服务提出的选项与实际决定分别留证，不能以准备完成代替承诺生效或实际履约。

<a id="section-3-4"></a>
## 3.4 场景应用：数智化方案怎样支持交易推进与兑现

共同标准、交易数据与知识、岗位应用、接口及智能体工作流，沿同一交易组合使用。客户背景进入机会与方案判断，最终承诺成为执行输入，履约证据进入验收和付款核对，偏差及剩余义务继续有去向。

<a id="section-3-4-1"></a>
### 3.4.1 商机核实与资源安排

销售在商机工作台中接住MTL的客户背景，关联本次沟通和购买条件。服务查询已有资料、比较前后说法，整理客户问题、已确认事实、推测与待核实项，帮助销售准备必要追问。方案与资源负责人同时查看适配难度、已投入支持和下一步要求，减少重复搜集背景。

销售主导客户沟通并确认购买依据，负责人决定推进、培育或退出及支持安排。确认结果和支持任务留在本商机中，供方案准备继续使用；新事实进入后更新原判断，失效线索及退回原因返回MTL。

<a id="section-3-4-2"></a>
### 3.4.2 需求、配置与报价评审

进入方案准备后，方案评审应用关联客户确认的交付要求、当前产品版本、配置与成本资料，服务整理需求、比较备选方案及报价差异，准备带依据的评审材料。产品、交付、供应、生产及财务核对同一范围的能力、现场、物料、资源和交易条件，明确核价由规则与程序计算。

客户核对需求及验收要求，各专业校准配置与例外，有权人确认可以对外承诺的范围。获准方案、报价依据和未决条件交给销售及商务谈判，影响成本、交期或能力边界的新条件再进入评审；超出现有供给的需要交IPD评估。

<a id="section-3-4-3"></a>
### 3.4.3 最终合同与开工交接

销售与商务在合同交接应用中核对谈判结果、批准范围及最终附件，服务比较修订差异、整理未决条件，供有权人确认。合同生效后的范围、配置、交期和付款要求通过接口进入订单、项目或批次，交付负责人据此组织资源、物料、现场及开工条件，相关岗位取得各自需要的内容和权限。

接收者确认最终版本、执行范围和条件能否支持工作，缺项返回补齐，容量与责任冲突进入协调。约定以付款为开工条件时，由财务核实到账并按批准安排继续；程序完成审批回传和明确的单据动作，服务准备交接材料并追查缺项。接收结果、批准与执行记录保留在本次交易中，供后续履约使用。

> **案例小贴士｜执行产物要适合岗位。** 制造企业订单与岗位权限试点中，车间按工况调整长度与支数，价格由下单端控制，办公室核对合同价格，工序单据送到对应岗位。这段材料未明确展示模型任务。女装批发企业局部使用照片与OCR支持自家ERP入库，经营者称三四百个SKU从约两小时缩到约二十分钟，范围为这项重复录入工作。

> **局部参照｜审批决定返回执行端。** 一次Odoo与飞书审批回传演示展示两级同意后回传并确认订单，这部分由程序完成。正式采用还需验证回传失败及重复处理，保证决定回到执行端。

<a id="section-3-4-4"></a>
### 3.4.4 履约进展与变更处置

履约应用按订单、项目与批次关联计划、任务、单据及沟通，服务比较约定与实绩，整理久未更新、矛盾或逾期的事项，准备原因假设及处理选项。交付负责人核实物料、产能、质量和客户配合等条件，再决定补齐、调整顺序或协调资源，专业人员确认实际完成与质量。

需要改变承诺时，销售和相关负责人核实范围、成本、工期、验收及收款影响，取得相应批准，并按约取得客户确认、形成有效变更。接口与工作流把变化或更正传给受影响岗位，服务准备通知和差异材料，接收者确认采用。新计划继续用于跟踪；受阻任务保留原因及处理结果，供验收与付款核对使用。

> **局部参照｜更正落到可确认的记录。** 一次使用测试数据的ERP核价单更正演示遇到锁单后，通过新建正确审核单完成更正，旧单保留、后续不再引用。实际业务也要核对使用者已经采用哪份依据。

<a id="section-3-4-5"></a>
### 3.4.5 成果提交与客户验收

交付人员在验收应用中取得有效合同、批准变更及各批成果，服务汇集配置、数量、测试或服务记录，比对约定范围并检查证据缺项，准备验收材料及获准的补齐任务。专业人员核实实际质量，内部预检与成果提交分别留下结果。

客户按约确认接受范围，退回项进入整改与复验，部分验收保留各自数量和状态。验收证据通过接口交给财务办理相应付款节点，并供后续服务接手；交付人员据反馈修正材料与准备方式，减少下一次核验和补问。

> **局部参照｜合格交付计入修订投入。** 兴城泳装商拍服务商复盘早期试点称，大量AI图仍靠PS补救，当时交出的图片甚至比真人拍摄更贵，这一阶段持续近一年。

<a id="section-3-4-6"></a>
### 3.4.6 收款条件与差异处理

财务在回款应用中按合同和变更查询付款节点，关联对应交付项、验收、开票与实收，程序计算明确的金额和核销关系。服务整理条件及证据缺项，对未收款提出带依据的原因假设，区分材料、验收、条款、支付及核销问题，供相应人员核实。

交付补齐成果与验收证据，商务处理条款差异，销售协调客户，财务确认币种、金额、到账与核销；催收方式、补偿和付款条件调整由有权人决定。确认后的任务由工作流继续跟踪，处理结果回到具体款项，并以实际到账复核是否解除阻碍。

<a id="section-3-4-7"></a>
### 3.4.7 剩余责任与经验反馈

收尾应用汇集剩余应收、质保义务、未决问题和后续负责人，服务整理当前依据、处置历史及交接材料，接收者确认对应范围与下一步。带有系统或持续服务交付的交易，还要交清账号、接口、资料及后续维护安排，使原负责人退出后必要工作仍有承担者。

销售、交付及财务沿本次机会判断、承诺与执行复查反复缺项，服务比较相似偏差和相反依据，准备规则、模板或Skill修订稿。责任人确认后投入后续工作，再看同类偏差是否减少；客群、产品及客户问题分别返回MTL、IPD与ITR，原合同的剩余义务继续保留去向。

<a id="section-3-5"></a>
## 3.5 效果检验与本章小结

检验从方案可用、场景改善推进到完整交易价值。先固定商机或合同批次、交易类型、质量要求、观察期与截止日，保留退出、未完成和有争议对象；分批交付、分期付款按各自范围追踪，币种、数量及金额口径保持一致，标准与范围变化分别记录。

**方案可用。** 以真实交易样本检查能否查到本次有效依据，完成评审、交接、变更、验收和款项核对，审批与系统动作能否按权限执行、更正及失败是否有人接手。使用者能够操作，维护者能够更新资料和检查运行，结果与对应交易一致。

**场景改善。** 沿3.1的问题检查机会准备是否推动客户下一步，承诺与配置差异、开工缺项、变更未采用、履约等待和验收返工是否减少，未收款是否找到并处理具体原因。观察背景重建、重复录入、材料准备及跨岗位等待的变化，同时核对产物是否被采用、反馈修订是否进入下一笔业务。

**整体价值。** 沿同批商机观察推进、退出、签约及实际投入，沿合同核对承诺兑现、合格验收与到账。回款比例以该批合同截至截止日累计到期的合同应收总额（含其中已收部分）为分母，以其中实际收回的对应金额为分子。争议和待核销继续列示，未到期另列。完整成本计入资料与方案准备、建设配置、履约执行、服务调用、系统操作、专业判断、核验返工、培训及维护；一次性建设说明分摊。同等质量、范围与规模下比较合格履约的完整投入，同范围待验收、未通过及整改成本一并计入；需要单位成本时，以同口径总成本除以客户按约验收接受的同类交付量。释放工时、现金支出、收入、毛利及资金回收分别观察，新增覆盖另看实际用途与结果。

据此决定保留、调整或扩大哪些应用，未完成和剩余责任继续跟踪。
