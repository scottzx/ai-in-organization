## C.1 为什么要单独列一张表

这份报告使用了一批在工作含义上彼此接近的词。它们在日常讨论中经常互换，但在这份报告里各自承担一件事。混用会直接导致判断出错——例如把"工作量减少"当成"成本下降"，或者把"定时执行"当成"组织在学习"。

下表按类别列出本报告的用法、容易混用成什么，以及它主要出现在哪一章。

## C.2 概念层

数字化、网络化、智能化的基本含义，参照相关政策与智能制造研究。导论简述政策出处和并行推进方向；第一章1.1解释智力服务的成本、响应与持续性特点，1.2说明任务交付，1.3检验经营价值，1.4再解释三化及其相互关系、服务参与建设与运行的共性机制。第二至第五章按业务问题追查原因，提出整体安排和建设交付物，再以场景应用说明使用。三化在整体方案中解释支撑作用，并通过场景和效果检验观察实际采用与结果。可信记录、可靠接续、分析与行动等具体要求为本报告应用整理，三化不作为固定先后阶段。

| --- | --- | --- | --- |

| **网络化** | 通过网络连接人员、设备、产品、系统和组织，支持信息交换、资源共享及业务协同；经营应用需落实共同对象、权限与接手安排 | 仅接通接口、发出通知或集中复制文件 | 导论0.4、第一章1.4、第二章2.3、2.4，第三至第五章的整体方案与场景应用、第六章 |
| **智能化** | 使系统具备感知、识别、预测、推理、优化、决策与执行，以及一定的学习和适应能力；按实际任务、技术条件与授权落实 | 看板汇总或人工分析即代表系统智能化；模型推理替代经营决策权 | 导论0.4、第一章1.4、第二章2.3—2.5，第三至第五章的整体方案、场景应用及效果检验、第六章 |

| **跨线诊断** | 围绕共同业务结果核实偏差及影响，比较原因假设与约束，形成行动并复核结果 | 只呈现各部门指标；相关性即为因果结论 | 第六章6.2、6.3 |

| **智力服务的三项特点** | 在适合委托的任务中，较低的处理成本、快速响应与可7×24小时持续承接，为扩大覆盖、缩短处理间隔和持续跟踪变化提供条件 | 调用便宜即总成本下降；生成快即业务完成快；全天运行即全流程无人处理 | 第一章1.1、1.3，第二章2.4的场景应用、2.5的效果检验 |
| **智力服务的三类作用** | 协助建造应用与工具、协调资料和工作传递、分析推理并支持检验；按实际能力落实到具体任务 | 与三化一一对应的三种产品；五类组织角色；服务自动取得责任和决策权 | 第一章1.4、第七章7.2 |
| **精细化管理** | 一种工作安排能力：说清任务的依据、执行分工、交接、验收和责任 | 增加更多记录、要求员工填更细的表格 | 术语补充 |
| **精益经营** | 一种研究取向：减少无效投入、使资源服务客户价值；是否改善按实际结果判断 | 净利润增长、成本下降等经营结果 | 第一至八章 |
| **工时** | 完成准备、执行、核验、返工、维护及人工判断所用的时间；按角色和任务记录 | 周期——后者含等待，不等于各人投入之和 | 第一章1.3、第八章8.4 |
| **词元成本** | 按词元计费的模型调用费用，按适用单价与计费方式记录；订阅及其他服务另列 | 价值尺度、效率指标、AI应用的全部成本 | 第一章1.3、第八章8.4 |
| **人工成本** | 各角色工时乘相应人时成本，覆盖本轮工作实际需要的人工投入 | 节省工时直接等于支出减少；必要判断已可全部交出 | 第一章1.3、第八章8.4 |
| **周期** | 沿同一业务对象从约定起点到终点的时长，包含等待 | 工时；不同起止范围的处理时间直接比较 | 第三章3.5、第八章8.4 |
| **有效业务周转** | 沿各流程约定的对象与起止点，比较合格结果形成和实际采用的完整周期、单位时间有效业务量及投入；组织同时看客户价值、履约质量、收益与现金回收 | 生成频率、调用量；将四种流程对象合成同一转化分母 | 第六章6.4 |
| **决策快** | 缩短从证据具备到有权人决定、再到相关流程实际生效的时间 | 只提前开会或发布决定，受影响工作尚未改变 | 第七章7.5.2 |
| **试错快** | 以可检验范围缩短从提出假设到取得有效结果、决定下一步的时间 | 试验次数或生成数量增加 | 第七章7.5.2 |
| **复制快** | 让新参与者采用经验证的方法，减少重新摸索并完成合格工作 | 未核实适用条件就直接套用旧方案 | 第七章7.5.2 |
| **切换快** | 决定调整后及时改变相关工作与资源，并处理已有客户承诺和剩余责任 | 不断插单，原工作及责任长期悬置 | 第七章7.5.2 |
| **Token** | 词元，是模型调用投入的一种观察单位，需结合具体计费方式 | 业务价值或全部应用成本 | 第一章1.3 |
| **单位合格交付成本** | 可归集的相关总投入除以合格交付数量，比较时说明范围、质量和规模 | 单次生成价格；不同交付范围直接相除 | 第二章2.5、第八章8.4 |
| **配套条件** | 选定任务所需记录、上下文、方法、系统动作、权限、验收与维护安排 | 一次性买齐的平台；与某一执行方式机械对应 | 第二章2.3、2.4，第六章6.2、6.3 |
| **数字化就绪度** | 针对具体工作，所需记录、上下文、系统动作和责任安排已经具备的程度，用于定位当前可验证的交付范围 | 企业统一成熟度等级；系统数量或采购金额 | 术语补充；第二章2.3、2.4的工作条件，第八章8.2 |
| **条件投入分摊** | 将相关一次性建设按约定使用范围、期间或合格交付量归集；持续运行另记，共用费用去重 | 用未来复用减少本期预算；重复分摊；漏记维护 | 第八章8.4；[草稿素材](../草稿箱/第二章-成本与效果-20261011.md#section-2-6) |
| **增量成本** | 与可比的原完成方式相比，因新安排新增的准备、调用、核验、返工或维护等投入 | 将所有既有质检和人工投入都算作新增 | 第三章3.5、第八章8.4 |
| **验证成本** | 核实产物能否使用、是否退回及如何修订的投入；新增部分须与原流程比较 | AI生成后全部审核工时都属于新增 | 第二章2.5、第四章4.4、4.5 |
| **有效替代／无效替代** | 在同一交付范围、质量要求与合格交付数量下比较前后总投入；数量变化时比较单位合格交付成本：**小于**为成本上的有效替代，**大于等于**为成本上的无效替代；范围扩大时另评新增价值 | 只看生成单价；漏记配套费用；用不同交付范围直接比较 | 第二章2.5、第八章8.4 |
| **必要投入** | 为质量、授权、责任和有效交付实际需要的投入；可以改进做法，不能仅因不直接生成产物而删除 | 尚未被替代的浪费 | 第六章6.4、第七章7.5、第八章8.4 |
| **未采用的产物** | 已生成但未进入实际工作的结果；应追查需求、质量、交接或采用问题 | 据此认定企业全部投入无价值 | 第六章6.4、第八章8.5 |

## C.3 工作结构层

| 用语 | 本报告用法 | 容易混用为 | 出现 |
| --- | --- | --- | --- |
| **端到端业务流程** | 沿客户或业务对象，从约定起点到结果完成组织跨部门工作，明确决策、交接与结果责任；MTL、LTC、IPD、ITR相互支撑，按需要并行和反馈 | 部门内部作业步骤；若干系统操作的串联；四条流程固定串行 | 第二至第五章 |
| **MTL** | Market to Lead，从市场到线索；识别市场与客户需求，形成销售实际接手且可跟进的有效线索，并利用跟进反馈调整市场工作 | 从商机退回线索；市场活动数量等于有效线索 | 第二章2.1、2.3、2.4、第三章3.4.1 |
| **IPD** | Integrated Product Development，集成产品开发；由相关职能共同判断需求、产品取舍与实现条件，形成能够销售和交付的产品或服务 | 研发部门单独出图或编码；全部客户要求立即进入开发 | 第四章 |
| **LTC** | Lead to Cash，从线索到回款；借鉴华为采用的端到端流程管理，分析线索进入销售后，各部门共同完成合同、履约、验收和回款的过程 | 只到签约的销售漏斗；由销售一人完成全部工作 | 第三章3.4 |
| **ITR** | Issue to Resolution，从问题到解决；组织问题受理、定位、处理、验证和客户确认，必要时连接产品与履约调整 | 工单已关闭；客服已回复即表示问题解决 | 第五章 |
| **流程责任人** | 对完整流程的结果、跨部门规则和受阻协调负责；具体职能仍承担各自专业决策和执行责任 | 每项操作都由一人完成；自动取得所有审批权限 | 第三章3.3.4、第四章4.3.4、第五章5.3.4 |
| **线索形成过程** | 沿市场触达、可追踪回应、候选线索、有效性验证与销售接手检查差距，以实际接手且可跟进的有效线索判断结果 | 名单、点击或询盘数量；将销售签约过程全部归入MTL | 第二章2.1、2.2、2.4、2.5 |
| **销售漏斗** | 在线索进入销售后，用商机与合同的阶段进展分析推进情况；按同批对象与一致截止口径观察转化 | 电话、会议、材料数量；把不同批次的期间数量直接相除 | 术语补充；第三章3.2、3.5 |
| **业务目标** | 希望改善的业务结果及可观察标准，如增加销售实际接手的有效线索、改善客户问题解决 | 上线工具、增加调用量 | 第二章2.3、2.5 |
| **整体思路／总体思路** | 从业务差距提出整项工作的核心做法，说明组织、协作与取舍怎样支持整体结果，进而明确方案与场景安排 | 重列流程节点；工具清单；重复现状分析 | 第二至第五章各章第3节，第六章6.3 |
| **子目标** | 为取得整体业务结果需要达到的具体改善，各项之间说明支持、约束和反馈关系，再向下拆举措 | 动作数量；单纯的流程节点名称；各自独立完成即可 | 第七章7.3的四个目标 |
| **业务举措** | 为实现目标采取的业务动作，如拓展线索来源、验证需求、落实交接 | 工具名称；一项举措只能采用一种技术 | 第二章 2.4 |
| **技术手段** | 支持具体业务举措的记录、系统连接、普通程序或AI能力，按任务质量与条件选择 | 业务目标本身；技术可做就应全部自动化 | 第二章 2.4 |
| **改造范围与依赖** | 将本轮业务目标、举措、输入条件、交接及先后关系说明清楚 | 全套平台采购清单；全部举措立即建设 | 第八章8.1、8.2 |
| **单次执行** | 围绕一次具体任务发起并完成，可在执行中优化提示、接入工具和沉淀经验 | 尚未自动化的低级阶段 | 第二章 2.4 |
| **定时执行** | 按预定时间或周期发起适合重复开展、已经验证的工作 | 所有重复任务；由业务变化发起的主动执行 | 第二章2.4、第八章8.3 |
| **主动执行** | 根据业务状态或环境变化，在约定条件与授权范围内发起任务 | 无边界自主行动；无人承担结果责任 | 第二章2.3、2.4，第六章6.3 |
| **Skill** | 按需加载的可复用任务方法与经验，含适用范围、步骤、工具用法及验收依据，需随真实任务反馈维护 | 已经具备无人值守能力；所有定时任务的技术前提 | 第一章1.2、第七章7.3目标1举措1.2 |
| **数字临时工** | 对按任务调用的智力服务的形象称呼；在明确目标、依据、工具和授权下完成一段工作，产物进入后续执行与验收 | 已经取得人的全部决策权或结果责任 | 第一章1.2、第二章2.4，第三至第五章的场景应用 |
| **任务** | 有边界的可执行单位：能说明目标、依据、产物、验收及责任 | 待办事项、一段工时、一个功能 | 第一章1.2、第二章 |
| **任务承接** | 接到目标与要求后，在获准范围内取得依据、调用工具、推进步骤，交出约定产物并说明未决事项，再进入验收与接手 | 一次问答或材料生成已经完成整段业务 | 第一章1.2、1.3 |
| **岗位** | 职责的集合，可随建造、执行、判断及协作安排调整 | 执行单位 | 第二章 2.1 |
| **交接** | 工作进入下一责任范围，接收者取得足够输入并确认可继续推进 | 文件发送或通知到达 | 第三章3.3.4、3.4、第五章5.4.2 |
| **验收** | 依据既定标准确认产物可用，记录通过或退回及后续去向 | 已生成、已上线、状态已关闭 | 第三章3.4、第四章4.4.4、第五章5.4.5、第八章8.3 |
| **上下文** | 下一执行者需要的来源、约束、决定、版本和未决事项 | 一段提示词或摘要 | 第三章3.3.4 |
| **组织上下文** | 按同一业务对象关联并持续更新来源、约束、决定、版本、当前状态与未决事项，让有权限的参与者据此继续工作 | 集中存放文件；未经确认的摘要即为当前依据 | 第三章3.3.4、第五章5.3.4 |
| **执行者 / 结果责任人** | 分别承担处理工作与确认业务结果的责任，可由不同人承担，按实际分工明确 | 工具账号归属；系统登记成功 | 第三章3.3.4、第六章6.3 |
| **建造者（builder）** | 持续把方法、上下文、工具、权限、交接和验收建成可运行能力，并按真实反馈优化 | 只有软件开发；制作一次工具即结束维护 | 第七章7.2、7.3目标1 |
| **执行者** | 按当前依据和授权承接具体任务，可由适合的人、智力服务或程序承担 | 所有执行都必须由人完成；完成操作等于结果已确认 | 第七章7.2 |
| **判断者** | 依据业务与专业标准确认产物是否可用，留下理由、证据及下一步 | 新增一层只签字的审批；只凭身份否决 | 第七章7.2、7.3目标2 |
| **管理者** | 集中协调跨业务、跨部门资源及异常，支持人员与能力发展 | 以传话、催办及逐人主观评分为主要职责 | 第七章7.2、7.3目标3 |
| **决策者** | 股东及核心管理层按治理与授权把牢方向、重要资源与重大取舍 | 每项日常专业判断都上交最高层 | 第七章7.2、7.5 |
| **精益管理** | 围绕客户价值和合格结果安排任务，减少重复解释、等待、返工与无效投入 | 单纯压缩人员；增加无助于业务的细记录 | 第七章7.2.3 |
| **官僚式管理职能** | 以没有新增判断的传话、催办、重复汇总和主观打分为主要内容；有条件精简 | 科层制中的所有授权、责任与必要协调 | 第七章7.2.2 |
| **按任务结果评价** | 事前约定质量、期限与采用，事后以证据相对量化，保留难度、外部依赖及共同贡献 | 单看生成量、调用量、工时或主管印象 | 第七章7.3目标4 |
| **任务路由与接力** | 依据任务要求、能力、权限和当前容量选择承接者；完成并验收后，将产物与当前状态交给下一承接者 | 所有任务固定交给同一角色；人和智能体拥有相同权限与责任 | 第六章6.3、第七章7.3目标3 |
| **能力网络** | 登记可用的人、智能体、工具和方法及适用范围、权限、容量与维护责任，使任务找到承接者 | 只有工具名称的清单 | 第七章7.3目标1的建造与复用、第八章8.3 |
| **知识网络** | 通过标识、索引及维护约定，让分散资料可发现、可核对、按权限使用 | 把资料都搬进同一产品 | 第六章6.2、第七章7.3目标1、附录D |

## C.4 重复运行、经验改进与智力飞轮

第六章聚焦共同经营取舍与整体协同，第七章引入建造者与判断者，讨论持续建造、实际采用及任务结果。7.4展开组织智力循环与飞轮，7.5检验后续相近任务是否持续改善；下表区分相应工作含义，并保留RSI技术参照的边界。

| 用语 | 本报告用法 | 它不支持的推论 |
| --- | --- | --- |
| **持续组织循环** | 交付以后继续监测，在条件满足时再次发起、执行和验收 | 定时器只能证明一项工作重复运行，组织是否已经学习要看别处 |
| **组织智力循环** | 反馈**实际改变**了后续的规则、有效上下文、方法或分工 | 保存记录只证明过程被留下，循环是否成立要看反馈有没有改变后续做法 |
| **智力飞轮** | 建造者持续改进能力，执行者采用，判断者验证，管理者协调，决策者把牢方向；后续相近业务在质量与收益成立的前提下持续改善有效业务周转 | 调用量增长、资料增加或单点提效已经证明四流程持续共同加速 |
| **RSI（递归自我改进）** | 系统利用自身能力参与对自身程序或策略的改进，再以改进后的能力继续改进；本报告借鉴其反馈改进执行能力的思路 | 组织保存对话或更新方法，就已实现技术上的递归自我改进 |

RSI的技术参照来自Zelikman等《[Self-Taught Optimizer (STOP): Recursively Self-Improving Code Generation](https://arxiv.org/abs/2310.02304v3)》2024年8月16日v3摘要：实验让调用语言模型的程序参与改进自身，模型本身未改变，作者据此说明这不是完整递归自我改进。第七章以持续建造、业务反馈、实际采用与后续结果检验组织改进，两者分别判断。

## C.5 证据标记层

导论0.6说明来源性质、实施阶段与效果口径，正文据此区分材料范围。

| 标记 | 取值 | 它说明什么 | 它不说明什么 |
| --- | --- | --- | --- |
| **来源性质** | 具名企业访谈、第三方实施者自述、经营者自述、现场演示、原型、需求讨论 | 这条材料以什么方式取得 | 效果是否被独立核验 |
| **阶段** | 已使用、局部使用、试点、原型、演示、需求与设想、市场探索 | 这项工作走到了哪一步 | 与效果无关：已使用不等于有效，原型不等于可交付 |
| **效果口径** | 每处效果都说明确切范围 | 这个数字适用于什么 | 适用范围止于所说明的那一段 |

**常见误读**（正文中逐处标注）：

- 工作量减少 **不等于** 成本下降；
- 节时 **不等于** 产出增加；
- 单点改善 **不等于** 全流程或经营收益；
- 能力已具备 **不等于** 采用已发生；
- 单点成本下降 **不等于** 总成本下降——增量成本可能只是没有被记账。

## C.6 组织形态层

| 用语 | 本报告用法 | 容易混用为 | 出现 |
| --- | --- | --- | --- |
| **被动式任务智能体** | 任务由人发起，工具处理，人再判断产物 | 能力不足的工具 | 术语补充 |
| **主动式任务智能体** | 在**约定条件下**发现问题、提出任务，并把结果带回组织 | 会自主行动的模型 | 术语补充 |
| **AI原生组织** | 研究性称谓；本文不据一次触发或工具上线认定企业已实现完整组织自动运行 | 已建成样板、某一种技术栈或触发级别 | 术语补充 |
| **一人公司（OPC）/ 一人团队（OPT）** | 一人借助工具跨职能承接工作的安排，仍需核验、专业判断及必要协作 | 所有企业共同终局；人数少等于总投入少 | 术语补充；第三章的一人主体案例 |

## C.7 使用这张表的方式

写作与评审时可以按三步检查一段表述：

1. **先看证据标记**：来源性质、阶段、效果口径是否齐全；
2. **再看概念**：是否把业务目标与技术手段、节省工时与减少支出混用；
3. **最后看结构**：是否把"重复运行"说成"组织学习"，把"生成完毕"说成"交付完成"。
