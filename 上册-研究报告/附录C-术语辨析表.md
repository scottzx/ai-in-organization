## C.1 为什么要单独列一张表

这份报告使用了一批在工作含义上彼此接近的词。它们在日常讨论中经常互换，但在这份报告里各自承担一件事。混用会直接导致判断出错——例如把"工作量减少"当成"成本下降"，或者把"定时执行"当成"组织在学习"。

下表按类别列出本报告的用法、容易混用成什么，以及它主要出现在哪一章。

## C.2 概念层

| 用语 | 本报告用法 | 容易混用为 | 出现 |
| --- | --- | --- | --- |
| **智力即服务**（intelligence as a service） | 部分智力工作能脱离具体人的工时安排，以服务形式被调用、计量和组合 | 「智能即服务」——中文里"智能"常指能力或智慧，与所引来源的译法不一致 | 第一章 |
| **精细化管理** | 一种工作安排能力：说清任务的依据、执行分工、交接、验收和责任 | 增加更多记录、要求员工填更细的表格 | 术语补充 |
| **精益经营** | 一种研究取向：减少无效投入、使资源服务客户价值；是否改善按实际结果判断 | 净利润增长、成本下降等经营结果 | 第一至五章 |
| **工时** | 完成准备、执行、核验、返工、维护及人工判断所用的时间；按角色和任务记录 | 周期——后者含等待，不等于各人投入之和 | 第一章1.4、第五章5.4 |
| **词元成本** | 按词元计费的模型调用费用，按适用单价与计费方式记录；订阅及其他服务另列 | 价值尺度、效率指标、AI应用的全部成本 | 第一章1.4、第五章5.4 |
| **人工成本** | 各角色工时乘相应人时成本，覆盖本轮工作实际需要的人工投入 | 节省工时直接等于支出减少；必要判断已可全部交出 | 第一章1.4、第五章5.4 |
| **周期** | 沿同一业务对象从约定起点到终点的时长，包含等待 | 工时；不同起止范围的处理时间直接比较 | 第三章3.3.4、第五章5.4 |
| **有效业务周转** | 从问题或需求进入，到合格结果被采用并支持业务推进的持续过程；比较同类任务的完整周期、单位时间有效交付及投入 | 生成频率、调用量；只缩短某一环节的处理时间 | 第四章4.2、4.4 |
| **Token** | 词元，是模型调用投入的一种观察单位，需结合具体计费方式 | 业务价值或全部应用成本 | 第一章1.4 |
| **单位合格交付成本** | 可归集的相关总投入除以合格交付数量，比较时说明范围、质量和规模 | 单次生成价格；不同交付范围直接相除 | 第二章2.3、第五章5.4 |
| **配套条件** | 选定任务所需记录、上下文、方法、系统动作、权限、验收与维护安排 | 一次性买齐的平台；与某一执行方式机械对应 | 第二章2.3、第四章4.3 |
| **数字化就绪度** | 针对具体工作，所需记录、上下文、系统动作和责任安排已经具备的程度，用于定位当前可验证的交付范围 | 企业统一成熟度等级；系统数量或采购金额 | 第二章2.2、第五章5.2 |
| **条件投入分摊** | 将相关一次性建设按约定使用范围、期间或合格交付量归集；持续运行另记，共用费用去重 | 用未来复用减少本期预算；重复分摊；漏记维护 | 第五章5.4；[草稿素材](../草稿箱/第二章-成本与效果-20261011.md#section-2-6) |
| **增量成本** | 与可比的原完成方式相比，因新安排新增的准备、调用、核验、返工或维护等投入 | 将所有既有质检和人工投入都算作新增 | 第三章3.3.4、第五章5.4 |
| **验证成本** | 核实产物能否使用、是否退回及如何修订的投入；新增部分须与原流程比较 | AI生成后全部审核工时都属于新增 | 第二章2.5、第三章3.3.2 |
| **有效替代／无效替代** | 在同一交付范围、质量要求与合格交付数量下比较前后总投入；数量变化时比较单位合格交付成本：**小于**为成本上的有效替代，**大于等于**为成本上的无效替代；范围扩大时另评新增价值 | 只看生成单价；漏记配套费用；用不同交付范围直接比较 | 第二章 2.3、2.5 |
| **必要投入** | 为质量、授权、责任和有效交付实际需要的投入；可以改进做法，不能仅因不直接生成产物而删除 | 尚未被替代的浪费 | 第四章4.2、4.4、第五章5.4、5.5 |
| **未采用的产物** | 已生成但未进入实际工作的结果；应追查需求、质量、交接或采用问题 | 据此认定企业全部投入无价值 | 第四章4.4、第五章5.5 |

## C.3 工作结构层

| 用语 | 本报告用法 | 容易混用为 | 出现 |
| --- | --- | --- | --- |
| **LTC** | Lead to Cash，从线索到回款；本章借鉴华为管理线索、管理机会点、管理合同执行的框架梳理销售职责 | 只到签约的销售漏斗；由销售一人完成全部工作 | 第二章 2.1 |
| **销售漏斗** | 用线索、商机到合同的阶段进展分析签约来源；围绕有效线索基数与各段转化率确定改进目标 | 电话、会议、材料数量；把不同批次的期间数量直接相除 | 第二章 2.2 |
| **业务目标** | 希望改善的业务结果及可观察标准，如增加有效线索、提高阶段转化率 | 上线工具、增加调用量 | 第二章 2.2、2.3 |
| **业务举措** | 为实现目标采取的业务动作，如拓展线索来源、验证需求、落实交接 | 工具名称；一项举措只能采用一种技术 | 第二章 2.3 |
| **技术手段** | 支持具体业务举措的记录、系统连接、普通程序或AI能力，按任务质量与条件选择 | 业务目标本身；技术可做就应全部自动化 | 第二章 2.3 |
| **改造范围与依赖** | 将本轮业务目标、举措、输入条件、交接及先后关系说明清楚 | 全套平台采购清单；全部举措立即建设 | 第五章5.1、5.2 |
| **单次执行** | 围绕一次具体任务发起并完成，可在执行中优化提示、接入工具和沉淀经验 | 尚未自动化的低级阶段 | 第二章 2.3 |
| **定时执行** | 按预定时间或周期发起适合重复开展、已经验证的工作 | 所有重复任务；由业务变化发起的主动执行 | 第二章2.3、第五章5.3 |
| **主动执行** | 根据业务状态或环境变化，在约定条件与授权范围内发起任务 | 无边界自主行动；无人承担结果责任 | 第二章2.3、第四章4.3 |
| **Skill** | 按需加载的可复用任务方法与经验，含适用范围、步骤、工具用法及验收依据，需随真实任务反馈维护 | 已经具备无人值守能力；所有定时任务的技术前提 | 第二章 2.3、2.4 |
| **任务** | 有边界的可执行单位：能说明输入、产物、验收与责任 | 待办事项、一段工时、一个功能 | 第二章 |
| **岗位** | 职责的集合。**本报告不主张它消失**，只主张承接方式改变 | 执行单位 | 第二章 2.1 |
| **交接** | 工作进入下一责任范围，接收者取得足够输入并确认可继续推进 | 文件发送或通知到达 | 第三章3.3.1 |
| **验收** | 依据既定标准确认产物可用，记录通过或退回及后续去向 | 已生成、已上线、状态已关闭 | 第三章3.3.4、第五章5.3 |
| **上下文** | 下一执行者需要的来源、约束、决定、版本和未决事项 | 一段提示词或摘要 | 第三章3.3.3 |
| **执行者 / 结果责任人** | 分别承担处理工作与确认业务结果的责任，可由不同人承担，按实际分工明确 | 工具账号归属；系统登记成功 | 第三章3.3.2、第四章4.3 |
| **任务路由与接力** | 依据任务要求、能力、权限和当前容量选择承接者；完成并验收后，将产物与当前状态交给下一承接者 | 所有任务固定交给同一角色；人和智能体拥有相同权限与责任 | 第四章4.3 |
| **能力网络** | 登记可用的人、智能体、工具和方法及适用范围、权限、容量与维护责任，使任务找到承接者 | 只有工具名称的清单 | 第四章4.3 |
| **知识网络** | 通过标识、索引及维护约定，让分散资料可发现、可核对、按权限使用 | 把资料都搬进同一产品 | 第四章4.3、附录D |

## C.4 重复运行、经验改进与智力飞轮

正文第四章4.3讨论怎样让本轮结果改善下一轮工作，4.4检验周转与收益。本表区分重复开展工作、改变后续方法与持续加快有效业务周转，并说明RSI在本报告中的借鉴范围。

| 用语 | 本报告用法 | 它不支持的推论 |
| --- | --- | --- |
| **持续组织循环** | 交付以后继续监测，在条件满足时再次发起、执行和验收 | 定时器只能证明一项工作重复运行，组织是否已经学习要看别处 |
| **组织智力循环** | 反馈**实际改变**了后续的规则、有效上下文、方法或分工 | 保存记录只证明过程被留下，循环是否成立要看反馈有没有改变后续做法 |
| **智力飞轮** | 在质量达标、收益覆盖完整投入的前提下，执行结果持续改进后续依据、方法与分工，借助复用和及时接力加快有效业务周转；效果按后续同口径结果检验 | 调用量增长、资料增加或单次提效已经构成持续加速 |
| **RSI（递归自我改进）** | 系统利用自身能力参与对自身程序或策略的改进，再以改进后的能力继续改进；本报告借鉴其反馈改进执行能力的思路 | 组织保存对话或更新方法，就已实现技术上的递归自我改进 |

## C.5 证据标记层

导论 0.2 给出三类标记，正文每条材料都据此表述。

| 标记 | 取值 | 它说明什么 | 它不说明什么 |
| --- | --- | --- | --- |
| **来源性质** | 具名企业访谈、第三方实施者自述、经营者自述、现场演示、原型、需求讨论 | 这条材料以什么方式取得 | 效果是否被独立核验 |
| **阶段** | 已使用、局部使用、试点、原型、演示、需求与设想、市场探索 | 这项工作走到了哪一步 | 与效果无关：已使用不等于有效，原型不等于可交付 |
| **效果口径** | 每处效果都说明确切范围 | 这个数字适用于什么 | 适用范围止于所说明的那一段 |

**常见误读**（正文中逐处标注）：

- 工作量减少 **不等于** 成本下降；
- 节时 **不等于** 产出增加；
- 单点改善 **不等于** 全流程或经营收益；
- 能力已具备 **不等于** 采用已发生；
- 单点成本下降 **不等于** 总成本下降——增量成本可能只是没有被记账。

## C.7 使用这张表的方式

写作与评审时可以按三步检查一段表述：

1. **先看证据标记**：来源性质、阶段、效果口径是否齐全；
2. **再看概念**：是否把业务目标与技术手段、节省工时与减少支出混用；
3. **最后看结构**：是否把"重复运行"说成"组织学习"，把"生成完毕"说成"交付完成"。
