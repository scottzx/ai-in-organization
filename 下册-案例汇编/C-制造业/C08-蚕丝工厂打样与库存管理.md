# C08 蚕丝工厂打样与库存管理

## 1. 企业介绍

本案例主体是一家二十多人的蚕丝工厂。企业涉及纱线、布料和成衣之间的生产与库存流转，经营者尝试借助AI制作适合内部业务的管理工具。

资料来自经营者访谈及内部系统讲述，经营者负责业务需求，同事参与工具使用和反馈。

## 2. 业务背景与改造目标

工厂希望看清打样、定样、大货生产、运输和入库的状态，并将同一产品的业务记录对应起来。已有ERP继续存在，新的内部系统围绕款号与阶段组织信息。

经营者还希望能够自行修改工具，使员工反馈进入下一轮调整。改造因此同时涉及业务记录和持续制作、维护系统。

## 3. 面临的问题

### 款号与流转状态

同一种布料可能做成多款衣服，库存与替代方案混在一起，纱线、布料和成衣之间的流转难以看清。经营者回顾曾有一笔数额较大的资金难从供应链和前端两头核清。

### 内部工具持续迭代

第一版工具不一定符合员工的实际操作。访谈举例，录错了500件，却没有删除按钮；业务细节只有进入使用后才暴露，需要继续修正。

## 4. 解决方案与实施过程

### 款号与流转状态

<a id="s-18-f01"></a>

**阶段：局部使用。**

经营者用AI协助整理需求，再用秒搭制作内部系统，将打样、定样、大货生产、运输和入库分成阶段，以贯穿生产周期的款号对齐已有ERP。工具支持记录产品和状态，同事按照实际业务使用；款号对应不意味着各系统接口全部自动打通。

### 内部工具持续迭代

<a id="s-18-f02"></a>

**阶段：局部使用。**

老板先借助AI形成需求文件，将业务补清后交给开发工具。系统形成框架后，员工开始使用并反馈问题，经营者根据截图等信息继续修改，包括处理误录500件时缺少删除按钮的问题。

AI降低需求整理和工具制作的门槛，经营者仍负责解释业务及推动迭代，员工通过真实使用检验工具。

## 5. 实施效果

### 款号与流转状态

内部系统已经展示并交员工使用，业务按款号与阶段组织，形成追踪打样至入库关系的基础。上述资金属于经营者回顾的历史核账困难，不能换写为系统已经追回或节省的金额。

### 内部工具持续迭代

访谈称累计进行了约1600次需求交互，表明工具在使用反馈中持续调整。软件月费约300元，只对应订阅费用；经营者与员工的需求和维护时间属于另一部分投入。

据光羽的平行世界节目受访者自述，工厂业务规模约2000万元；访谈中更高的当年销售额属于预计，本书不采用。业务规模不能归为AI已经创造的新增利润。

## 6. 分析与启示

**本书分析：**统一款号与阶段，先让业务对象和状态可追踪，再谈进一步连接系统，是本案的实施线索。系统制作与运行也应分别看待：AI帮助做出工具，工具运行后仍需要人定义业务、检查使用和处理错误。

评价完整效果时，应检验货物流转和账目是否更可靠，同时计入持续需求交互、修改和维护的投入。低订阅费不能单独代表低总成本。
