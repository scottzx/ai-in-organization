# C23 汽车零部件供应链经营分析

[下册索引](../README.md) · [本行业索引](README.md) · [上册研究报告](../../上册-研究报告/README.md)

## 1. 企业介绍

案例企业为一家匿名的汽车供应链企业，主要向下游销售汽车维修零部件。零部件从上游买入，在厂内经组装、组合及加工处理后成品交付；日常经营涉及六类事项——接单、排产、采买、存货、出货、收款，需要同时管住。企业此前已上线ERP。本案例依据项目实施者的访谈整理。

本篇按来源披露的加工组装活动及其制造企业身份归入C制造业。销售自产产品与轻生产形态不单独构成批发零售业归属；现有资料未披露制造与转售的收入构成，本书的研究编排不作为企业正式统计行业认定。

## 2. 业务背景与改造目标

企业有业务系统，经营者却仍难以直接看清一笔订单与采购、库存、发货、应付款和回款之间的关系。项目因此选择保留ERP，先改善经营数据的可见性，并把需要关注的异常推送出来。

本次改造的阶段目标是让经营者能够沿业务关系核对进展和依据，而不是重建一套交易系统。

## 3. 面临的问题

老板要知道订单走到哪一步，仍需向不同人员询问；要核对应付款，也难以直接看清它由哪些业务记录形成。记录存在于系统中，但相关数据没有按经营者关心的问题连起来。

这使订单进展、库存状态和资金依据需要反复询问与核对。单独查看一项记录，难以判断其他环节是否存在异常，也不便识别可能发生的重复订货。

## 4. 解决方案与实施过程

<a id="c-20-f01"></a>

**阶段：局部使用。**

实施团队围绕订单、采购、库存、发货和回款，重新组织现有数据之间的关系。项目保留原ERP，通过匹配与核对，使经营者可以查看库存和应付款的依据，并利用飞书提供基础异常通知。

原文用“十万元应付款”和“4980个扳手”说明数据关系：经营者关心的不是一个孤立金额或数量，而是这些记录对应什么业务。两组数字是说明性例子，不是本项目追回款项或节省损失的统计。

## 5. 实施效果

据实施者自述，项目刚上线，基础异常通知和部分经营可见功能已经实现。库存与应付款的形成依据更可追溯，经营者有了沿业务关系查看和核对的入口。

这一结果属于局部经营可见性与通知能力。异常被发现后是否完成处置，以及采购节省、成本或利润是否改善，仍不能由刚上线的功能表现推得。

## 6. 分析与启示

**本书分析：**本案例的机制是围绕经营问题组织已有记录。ERP承担原有交易与记录，新增能力帮助使用者把分散的数据联系起来，并提示异常；这比单纯再增加一张报表，更接近经营者实际要回答的问题。

后续评价可以沿一项异常继续观察：它是否被理解、是否得到处理，处理是否改变采购或资金结果。看见异常是阶段成果，经营改善还需要处置及业务结果支持。
