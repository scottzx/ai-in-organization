# C03 制造企业驻场需求梳理

[下册索引](../README.md) · [本行业索引](README.md) · [上册研究报告](../../上册-研究报告/README.md)

## 1. 企业介绍

本案例涉及一家制造企业和开展驻场服务的实施团队。企业已有NC、OA等系统，双方在现场讨论如何整理业务数据并安排后续建设。

资料是驻场需求会议片段，呈现的是建设之前的业务理解和范围讨论。

## 2. 业务背景与改造目标

企业希望采集业务信息，并进一步用于协作看板和问答等应用。据受访者介绍，实施方原先预留约一个月盘点系统，现场发现既有系统和业务关系比预想复杂。

讨论以报销为例，将发票录入连接到订单与产线的费用归集，用于明确后续系统应处理什么业务关系。

这一讨论的外部背景是发票本身正在数字化。按《关于推广应用全面数字化电子发票的公告》（2024年第11号），全面数字化电子发票自2024年12月1日起在全国推广，票面要素包括项目名称、规格型号、数量、单价、金额、税额等；受票方可以通过税务数字账户对发票“入账与否打上标识”。也就是说，发票数据本身越来越容易被结构化取得，但它记载的是交易内容，不记载企业内部的订单号或产线。

## 3. 面临的问题

发票被识别并写入OA以后，还不能直接支持成本分析：费用究竟属于哪张订单、哪条产线，仍需要明确。单一识别动作与经营需要之间，缺少可用的归属关系。

按《企业产品成本核算制度（试行）》，制造企业一般按产品品种、批次订单或生产步骤确定成本核算对象（第九条）；费用能确定由某一核算对象负担的直接计入，由几个对象共同负担的，要选择合理的分配标准分配计入（第三十四条）。报销发票要进入成本分析，就必须先回答它属于哪一个核算对象，或者按什么标准分摊。

NC与OA的实际情况也影响实施安排。尚未盘清的数据关系，会直接影响采集、看板和问答能够覆盖的业务范围。

## 4. 解决方案与实施过程

<a id="s-04-f01"></a>

**阶段：预计。**

驻场会议先从实际业务对象展开讨论。实施方用报销说明，不能只设计识别发票，还需要确定识别后的费用如何关联订单和产线，再据此安排数据整理与系统建设。

视频中的智能采集、协作看板及七八十个智能体属于一期计划。AI识别、业务记录和看板是拟议工具；现场已经发生的工作是双方核对需求和数据关系，尚未展示这些工具稳定执行。

## 5. 实施效果

据受访者介绍，需求讨论把问题从发票录入推进到费用归属，也揭示了既有系统盘点的复杂度。这是当前材料能够呈现的阶段成果。

一期应用清单和智能体数量仍是计划，本案尚处于预计阶段，不能用方案规模替代实际交付。

## 6. 分析与启示

**本书分析：**建设范围应从经营问题倒推。费用归属订单与产线的关系明确以后，识别结果才有可能进入成本分析；在此之前扩大工具清单，会放大后续对接工作。发票数字化解决的是“取数”，归属规则仍要由企业自己定义，这部分工作无法由识别工具替代。

类似项目可以先检验少量真实费用能否被正确归属，再决定采集与分析范围。应用数量应随可用数据和实际交付扩大，而不作为需求阶段的效果指标。
