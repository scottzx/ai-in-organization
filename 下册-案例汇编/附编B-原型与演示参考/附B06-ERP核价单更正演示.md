# 附B06 ERP核价单更正演示

[下册索引](../README.md) · [本行业索引](README.md) · [上册研究报告](../../上册-研究报告/README.md)

## 1. 企业介绍

本篇介绍账号作者“老关聊企业数字化 - 企业AI落地实操”发布的ERP核价单更正演示。材料使用明确标注的测试供应商、物料与核价单，展示AI执行系统动作时遇到规则限制的过程。

## 2. 业务背景与改造目标

演示先要求AI建立一张含税10元的核价单并审核，再将价格改为5元。任务需要在ERP允许的动作中处理价格更正，并由人回到系统确认结果。

## 3. 面临的问题

核价单审核后被系统锁定。AI在审核前没有提醒这一限制，后续反审核、修改、删除和作废都没有顺利完成，原先设想的直接修改路径因此受阻。

AI中途还提出从数据库处理的建议。演示暴露的具体问题是，更正意图与系统允许的动作之间存在差距，需要重新选择能够完成业务目的的正式路径。

## 4. 解决方案与实施过程

<a id="s-15-f01"></a>

**阶段：演示。**

作者让AI建立并审核含税10元的测试核价单，随后提出改为5元。遇到锁单后，AI尝试的反审核、修改、删除和作废均未顺利完成，并承认自己在审核前没有提醒锁单。

最终采用的处理方式是新建一张5元核价单并审核。作者回到ERP确认新单；原10元单保留，后续不再引用。演示中出现的数据库建议属于问题路径，最终结果由新建正确单的正式操作取得。

## 5. 实施效果

演示最终建立并审核了新的5元核价单，由作者在ERP中确认。更正结果对应新单，历史10元核准单仍然保留，并未被改为5元。

这一过程呈现了测试数据下的锁单限制、失败尝试和更正路径，不能作为客户生产环境中的实施效果。

## 6. 分析与启示

**本书分析：**AI执行企业系统动作时，需要把业务意图与系统规则连接起来。审核前说明锁单影响，能够帮助人判断是否继续；遇到限制后，处理方案仍应落在系统允许的正式动作上。

结果确认也要对应具体记录。本例中，新的正确单、旧单的保留和后续使用安排需要一起理解，才能准确判断更正完成了什么。评价类似应用时，应检查系统返回及人工确认，而不能只凭AI对动作的口头说明。
