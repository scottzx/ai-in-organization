# J02 招商银行大模型工作项梳理与应用


[下册索引](../README.md) · [本行业索引](README.md) · [上册研究报告](../../上册-研究报告/README.md) · [中册J01 银行](../../中册-行业解决方案/J01-银行.md)

## 1. 企业介绍

招商银行成立于1987年，总部位于深圳，在上海证券交易所和香港联交所上市，提供批发及零售银行产品和服务。据其2025年度报告，截至2025年末本集团资产总额130705.23亿元，研发人员11051人，占员工总数的9.09%；2025年信息科技投入129.01亿元，占本公司营业收入的4.31%。[1]

本篇材料来自该行2025年度报告和2026年3月30日年度业绩发布会问答实录（根据录音整理）。行业层面的银行数字化方案见[中册J01 银行](../../中册-行业解决方案/J01-银行.md)。

## 2. 业务背景与改造目标

据业绩发布会实录，该行在2023年提出建设智能银行的目标，2023—2024年进行探索，2025年提出“AI First”战略，要求在全行全面推行大模型应用。[2] 年度报告把这一方向表述为全面拥抱以大模型为代表的新一代人工智能，做好数字金融。[1]

改造目标并非建设单个对话产品，而是让大模型进入零售、批发、风控、运营、办公和研发等岗位的日常工作，并在前中后台提升自动化处理与智能决策水平。[1]

## 3. 面临的问题

银行岗位多、流程长，大模型能在哪些工作上发挥作用、发挥到什么程度，事先并不清楚。发布会上，该行首席信息官指出，大模型应用本质上是概率应用，不确定性较高，需要反复调试和迭代；大模型仍存在幻觉，应用仍会犯错，而银行业要求严谨，监管态度审慎。[2]

因此，该行需要同时解决三件事：确定优先投入的场景，缩短应用从试验到投产的周期，并控制错误风险，使岗位人员继续承担责任。

## 4. 解决方案与实施过程

<a id="cmb-2025-f01"></a>

**阶段：已使用。**

据发布会实录，该行先对全行员工所做的工作进行梳理，识别大模型可以发挥作用的独立工作项，截至2026年2月末共识别出1588个；科技部门与业务部门再按量化标准把工作项分为高、中、低价值三类，优先投入高价值工作项。[2] 问答后段，同一位发言人又提到共梳理3400多个工作项、其中1500多个大模型能够发挥作用，两组数字口径不同，本篇分别记录。[2]

工程上，该行称一个大模型应用或智能体大约要迭代6次才能投产；通过改进大模型工程体系，平均迭代周期从2024年的32天缩短到8天。[2] 基础设施方面，年度报告称该行完善“云+AI+中台”底座，2025年日均Tokens吞吐较2024年增长10.1倍，落地领域专精模型183个。[1] 发布会实录补充，该行结合开源搭建推理平台，智算卡7×24小时平均利用率为35%。[2]

应用以岗位“小助”形式嵌入流程：零售条线的系列小助用于客户经营、经营分析和财富投研；批发条线的“CRM小助”服务对公客户经理；风险条线的“风险小助”嵌入作业流程；运营条线的“营小助”用于数字助理、运营知识问答、业务智能审核、服务对练和风险事件分析。[1] 研发领域的“编码小助”从Copilot模式向Agent模式演进。[1] 员工侧，该行面向各岗位开展AI能力认证和全员培训。[1]

发布会实录强调，银行业的大模型应用总体是“人+Agent”模式，部分岗位完全由Agent替代人目前还不可行；该行同时投入资源研究抑制幻觉的方法。[2]

## 5. 实施效果

据年度报告，截至2025年末该行在多个领域落地856个场景应用，报告期内节约人工1556万小时；对公客户经理、信贷人员、运营人员使用相应小助的用户覆盖率分别为80.13%、80.32%和100%，编码小助研发人员覆盖率超过97%。[1] 发布会实录称，大模型在高、中价值工作项的落地比率为69%，在低价值工作项为39%。[2]

发布会实录还列出若干业务环节的变化：RM小助支持超过1万名金葵花客户经理，2025年客户经理人均有效触客次数提升14%，客均交易规模提升20%；小企业尽调报告82%的工作量由大模型应用替代人工；70%的审贷官批复意见可在AI辅助下由系统追踪；AI风险预警比原来人工管理提前42天。[2]

上述数字均为该行自述口径。节约人工小时是工作量折算，不等于减少的员工人数或已实现的成本节约；触客和交易规模的提升也受市场等其他因素影响，来源未给出对照方法。

## 6. 分析与启示

**本书分析：**本案的起点是工作项清单，而不是技术清单。先把员工工作拆成独立工作项，再由科技和业务共同评估大模型能发挥的程度，使投入顺序有了可讨论的依据，也让“落地比率”可以按价值层级分别统计。对其他银行而言，这种梳理本身就是可复用的方法，即使所用模型和平台不同。

第二点是把迭代周期作为工程指标管理。概率性应用需要反复调试，32天到8天的变化说明，评测、发布和回滚等工程能力决定了场景能落地多快。第三点是以岗位小助的形式嵌入既有流程，并用用户覆盖率跟踪使用情况，覆盖率衡量的是使用面，还需配合质量和差错指标判断效果。

需要注意的局限有三。其一，同一场发布会给出1588和3400多两组工作项数字，口径未说明，引用时应分别标注。其二，节约1556万小时等效果为银行自述，未经独立审计，且难以与人员规模或成本直接换算。其三，该行信息科技投入规模较大，并有既有云平台和研发队伍，中小银行借鉴时应先评估自身数据、平台和人员基础，从少数高价值工作项起步，并保留人工复核和责任认定环节。
