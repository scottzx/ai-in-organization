# L08 零一数科AI应用

本篇场景：[岗位工具与客户管理](#s-11-f01) · [部门连接与组织设计](#s-11-f02) · [招聘工具与技能服务](#s-11-f03)

## 1. 企业介绍

本案例主体是零一数科，资料为具名企业访谈与岗位工具展示。本篇涉及内容生产、KA客户管理及财务收款、招聘，以及把内部技能做成服务的探索。

结合企业公开介绍与受访者身份核对，主体为零一数科（深圳）科技有限公司，主要提供品牌全域营销、私域及视频号代运营服务。本篇据此归入L租赁和商务服务业，内部工具开发与客户所属行业作为场景信息保留。

访谈同时呈现当前使用的工具和未来组织设计。本篇按三个场景分别展开，避免把已经运行的局部工具与规划中的部门协同合并为同一项成果。

## 2. 业务背景与改造目标

在内容业务中，企业希望把负责人的判断带入脚本点评和每周复盘；在KA客户管理中，需要适应长周期、多部门协作，并连接财务收款。据受访者介绍，员工也尝试让工具围绕一段完整工作发挥作用，而不只处理一个孤立步骤。

在这些局部工具的基础上，企业提出由部门FDE连接工具、形成跨部门协作的方向。招聘工具则围绕项目的真实缺口组织人才信息，技能服务探索尝试把内部工作能力转为对外服务。这些目标处于不同阶段。

2026年10月发表的一篇企业创始人专访补充了同一企业的说法。专访称，招聘已跑通从生成岗位描述、匹配候选人到整理面试纪要的流程，所有决策确认节点仍由人负责；HR团队人员数量压缩超过50%。专访还提到企业每双周开办技能制作工作坊、员工可把岗位流程整理成技能供同事调用，以及对外提供深入客户梳理业务流程的FDE服务。这些仍是企业自述，口径与视频不完全相同（专访讲的是用10个人重新设计组织），本书不将其数字并入本案各场景的结论。

## 3. 面临的问题

### 岗位工具与客户管理

内容判断依赖负责人的经验，脚本点评、发布和复盘需要把这种判断带入日常工作。KA客户周期较长、涉及多个部门，客户管理工具也需要适应这些协作关系，并与收款衔接。据受访者介绍，社保账单合并则是另一项耗时的重复任务。

### 部门连接与组织设计

局部工具形成以后，还要考虑怎样将它们连起来。访谈把“连点成网”作为未来安排，说明工具可用与跨部门协同之间仍有组织设计工作。

### 招聘工具与技能服务

招聘需要围绕项目实际缺口识别人才，而不只按通用岗位描述筛选。把工作技能做成对外服务时，内部任务可用又只是起点，客户购买的是能够持续交付的服务。

## 4. 解决方案与实施过程

### 岗位工具与客户管理

<a id="s-11-f01"></a>

**阶段：局部使用。**

内容团队把负责人的判断用于脚本点评和每周复盘，数据回到工具后，负责人仍参加周会。有员工把制作、发布和反馈连在一起，承担从起点到终点的一段流程责任。

另一个例子是按KA客户长周期、多部门协作设计CRM。受访者称，团队用两个月搭建工具，并将其连接到财务收款。社保账单合并也形成了单独的工具应用。上述工作属于当前工具实践，不能与部门FDE连接的未来规划合并计算。

### 部门连接与组织设计

<a id="s-11-f02"></a>

**阶段：预计。**

访谈提出在部门配置FDE，希望由这些角色连接已有工具，形成跨部门协同。社区制、分配方式和新业务底座也属于未来组织设计。

据大树AI创业圈｜TTM节目受访者自述，业务高峰期曾有1000多人；讨论中的“1000人变7人”在正文解释为七类核心角色，不是已经裁员到七名员工。十倍增长指向新底座与新业务的设想，也不是既有业务已经增长十倍的结果。

### 招聘工具与技能服务

<a id="s-11-f03"></a>

**阶段：局部使用。**

招聘工具围绕项目真实缺口组织人才标签，再结合岗位与候选资料生成问题。模块负责人也尝试以承担整段流程的方式设计自己的工具，使功能贴近业务用途。

访谈同时讨论把技能做成服务、按调用收费等方向。这里既有当前尝试，也有未来收入判断；招聘标签与题目工具的展示，不直接证明技能服务已经形成规模交易。

## 5. 实施效果

### 岗位工具与客户管理

访谈自述和工具展示支持的阶段结果，是内容点评与复盘工具、CRM以及社保账单合并等局部应用已经形成。受访者称，社保账单合并的耗时大幅缩短；该说法未能核实，本书不采用具体时长，只对应账单合并任务，不能扩展为内容、客户管理或整体经营的节时结果。

受访者所述CRM的两个月是搭建时间。它与财务收款的连接描述的是工具范围，不是已经提高收款金额或回款率的证明。

### 部门连接与组织设计

部门FDE连接、社区制和七类核心角色仍属预计。本场景呈现的是企业提出的组织方向，不提供已运行的跨部门协同效果。

### 招聘工具与技能服务

招聘标签和题目生成工具已经有展示，表明项目缺口可以进入招聘准备工作。技能服务的商业化仍需与内部工具使用分别理解，本篇不把未来收入判断写成已经取得的规模收入。

## 6. 分析与启示

**本书分析：**本案例呈现了从岗位工具走向协同设计的过程。当前可借鉴的做法是围绕业务对象做工具，把负责人的判断、工作记录与后续反馈放进具体任务，并让部分员工承担一段完整流程。

工具之间要形成协同，还需要把输入、产物和责任连接起来。部门FDE是企业提出的一种未来安排，其有效性应由实际协作结果检验。把能力对外出售时，评价对象也要从内部任务可用转向交易、续费和持续交付，不能用内部工具的节时替代商业结果。
