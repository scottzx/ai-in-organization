# 怎样使用行业解决方案

中册集中展示各行业的数字化解决方案，以及在这些方案基础上增加智力服务的具体做法。读者先认识本行业的总体架构、主要模块、建设内容和业务价值，再结合本企业条件选择复用、补建与增强的范围。

本册的行业方案以已收集的指南、报告、白皮书及企业实践为依据。行业数字化体系是正文主体，智力服务围绕各业务模块增加建设、协调与分析作用；通用的企业实施方法统一见[上册第八章](../上册-研究报告/08-实施建议-从改造机会到可验证行动.md)，各行业章集中解释专业模块、适用条件、业务价值及服务新增作用。

## 一、先认识行业数字化方案本身的价值

企业需要理解本行业哪些能力值得形成。工程机械的设计、工艺、零部件制造、总装、质量和售后，钢铁的原料、冶炼、轧制及经营协同，项目和服务企业的设计、资源安排与客户交付，各有业务对象、专业工具、数据模型及人员条件。行业数字化方案帮助企业认识这些能力怎样配合，以及一处缺口会影响哪些工作。

行业参考架构呈现整体关系，应用模块说明具体怎样工作。例如，设计工具和专业模型支持产品表达、仿真及验证，版本管理让工艺、采购和制造取得有效依据；生产执行把计划、工单与现场状态关联，质量模块将要求、检测与批次对应，支持放行及追溯。这些建设本身能够改善业务，需要相应的数据准备、软件配置、现场工程、专业验证、实际采用和维护。

本册配合原图展开主要模块，使读者能够理解和选择建设内容。

| 模块讲解要点 | 行业方案需要说明什么 |
| --- | --- |
| 业务任务与运行方式 | 谁在什么条件下工作，输入来自哪里，怎样处理，形成什么产物，交给谁使用。 |
| 业务功能与专业工具 | 软件、设备和模型怎样记录、设计、计算、仿真、分析、执行或控制。 |
| 建设内容与条件 | 需要配置或开发什么，准备哪些数据与规则，完成哪些设备、网络、集成及专业工作。 |
| 模块关系与交付 | 上下游怎样交换版本、状态和资源条件，形成哪些可用系统、模型、接口及操作维护资料。 |
| 业务价值与验收 | 对产品、质量、交期、设备、资源、服务或经营有什么作用，怎样核验可靠运行、实际采用和业务结果。 |

行业方案提出的联网、工业模型、设计仿真、优化排程、视觉检测、预测维护和自动控制，均作为数字化建设内容展开。企业是否已经具备这些能力，需要核对实际建设和使用情况。企业即使本轮只建设其中一部分，也应能读懂该模块的价值、必要条件及前后依赖。

## 二、围绕业务模块引入智力服务

在上述体系上，智力服务可以参与建设，也可以承接运行中的资料理解、协调与分析任务。其新增价值承接上册讨论的成本、响应和持续性特点，落实到具体工作变化。

| 服务作用 | 围绕业务模块增加什么 | 需要检验什么 |
| --- | --- | --- |
| 协助建造 | 整理需求与规则，设计数据结构，辅助开发工具、适配接口、准备测试及交付资料。 | 部分开发和试验投入是否下降，可用工具是否更快形成，工程质量、采用与维护能否成立。 |
| 协调传递 | 利用企业可用的系统和连接理解不同表达，核对变化，整理共同背景、缺项及接手事项。 | 查找和转述等待是否减少，变化是否准确进入相关岗位与执行安排。 |
| 分析推理 | 利用可取得的数据、知识、模型和专业工具准备原因假设、比较方案，并衔接获准处理。 | 分析是否更及时、覆盖是否扩大，产物是否被采用，行动与业务结果是否改善。 |

[3C外贸企业](../下册-案例汇编/F-批发与零售业/F09-3C外贸企业AI自建业务系统.md#s-07-f01)的经营合伙人借助AI建设业务系统，集中产品资料后支持PI和装箱单生成，日常输出依靠系统与规则，属于局部使用。他也回顾了30天制作大系统未达预期的尝试，强调同事能持续使用。[AI辅助ERP开发](../下册-案例汇编/I-信息传输软件与信息技术服务业/I02-AI辅助ERP开发与架构探索.md#s-17-f01)则呈现需求定义、检查偏离与人工修正。建设方式的变化已经提供新的可能，具体价值仍由可用成果、实际采用和后续维护检验。

服务可以协助开发连接工具，再利用连接整理依据和准备分析。专业程序承担适用计算、优化求解与控制，专业人员确认结果及适用性，相关负责人决定重要投入和承诺。评价新增价值时，计入资料整理、专业核验、现场工程、集成、返工、培训及维护，基础建设价值、项目总体改善与服务贡献分别记录。

## 三、不同基础的企业怎样选用方案

基础薄弱的企业，可以从行业数字化方案认识必要能力，再围绕实际产品、客户和现场条件选定建设范围。表格、文件及人工处理已有的有效部分继续使用，关键对象、规则、版本和责任需要落实。新的开发方式降低了部分局部工具的试验门槛，使企业有机会在补基础时一同设计连接及适用的智能任务，更早形成协同能力。

已有多种系统的企业，则对照行业应用模块，检查企业已建功能是否被使用、数据和模型是否有效、现场与后续岗位能否接手。有效的软件、设备和经验继续复用，未建全、未采用或衔接受阻的部分按实际差距改进。系统数量、企业规模和是否使用Excel，均需回到实际业务和采用情况判断。

三化含义沿用[上册第一章1.4](../上册-研究报告/01-智力即服务.md#section-1-4)：数字化让对象与过程能够表达、计算和处理，网络化连接分散的对象与工作以支持协同，智能化使系统根据情况分析、判断并开展相应处理。三者相互支撑，建设次序按业务与技术依赖确定。

同一家企业在不同模块上可以采用不同安排。例如，生产进度不清可能需要补工单、工序与现场记录，也可能需要改进已有MES的报工质量、订单关系和计划变更传递。智力服务的参与位置随实际缺口确定。通用的“摸清现状—确认目标—画蓝图—制定计划”及建设、验收、反馈方法，统一见[上册第八章](../上册-研究报告/08-实施建议-从改造机会到可验证行动.md)；[行业能力对照表](附录A-行业方案选用与能力对照表.md)用于辨认参考能力、企业实际基础及服务增量。

## 四、行业章节与资料怎样对应

各行业章依次说明行业特点与业务目标、总体架构、主要数字化模块、智力服务新增作用和适用结论，章末单列参考资料。读者可以按企业类型和业务模块选择所需能力，再结合上册第八章组织实施。例如，[工程机械](C01-工程机械.md)将研发、工艺、制造、质量、供应链和售后放在同一体系中，便于整机厂与配套企业分别判断建设重点。

经营对象和专业流程不同的行业分别选读：[住宿](H01-住宿.md)以房间、房晚和接待为主线，[餐饮](H02-餐饮.md)以菜品、食材和供餐订单为主线；[农业](A01-农业.md)、[林业](A02-林业.md)、[畜牧业](A03-畜牧业.md)和[渔业](A04-渔业.md)分别组织生产对象及专业模块。同一上位指南可以支持多个行业，但图示和案例按实际适用范围引用。各篇当前覆盖的企业类型、保留的产业链关系和需继续补充的方向，见[行业分篇说明](../索引/中册行业分篇说明.md)。

[行业资料库](../索引/工信部行业数字化转型资料汇总.md)提供发布或编制机构、版本、适用范围及PDF页码。总体指南、专业模块、政策任务和研究框架分别按文件的适用范围使用，多份资料承担的作用在章内说明；原图保留出处、图示关系及公开入口，模块归并或编者补充注明对应依据。

企业实践在下册按主体维护，正文就近引用相应过程。局部使用、试点、预计与后续方向保留来源披露的阶段，实绩与方案建议分别表达。参考资料中的评级、所引项目成效及其他企业的收益，均按各自证据范围理解；本企业建设是否有效，由实际运行、完整投入和业务结果验收。
