# 第二章　建设实施：从行业方案到可验证的业务结果

一芥智能研究院｜《企业数智化转型研究报告》中册｜初稿 v0.1｜2026年10月18日

[中册目录](README.md) · [上一章](01-既有行业方案与智力服务.md) · [下册企业案例](../下册-案例汇编/README.md)

行业图谱帮助企业找到需要的模块，实施则要把它们建成可以持续使用的能力。沿一项真实业务明确结果、核实条件，组合必要的基础建设与智力服务，再完成集成、采用和效果验证，才能决定下一轮投入。企业可以在同一范围内并行补齐数字化、网络化和智能化条件，建设次序按业务依赖与资源安排。

<a id="section-2-1"></a>
## 2.1 确定目标、模块与本轮范围

### 从实际业务和接收者核实现状

选择能够追踪的一类工作，例如设计变更、订单排产、质量处置或设备维修。执行者与接收者共同核对当前怎样完成、产物交到哪里、哪些地方需要补问、等待或返工，保留实际资料和时间记录。区分已经发生的差距、对原因的猜测与尚待确认的条件。

把这些工作放回行业原架构，列明涉及哪些模块、系统、设备与外部协作方。参考方案的能力要求、企业已经具备的能力、本轮补建的基础和新增服务分别记录。先有一份可用的企业实际基线，才有条件比较建设带来的变化。

[压力容器企业](../下册-案例汇编/C-制造业/C04-压力容器企业成本核算需求梳理.md#s-05-f01)在需求讨论中要求先处理财务、采购与仓库，因为每台设备的实际成本不清会影响下一轮报价。来源记录的是需求核对和顺序调整，尚未形成成本核算交付。该过程显示，实施顺序应当沿实际经营所缺的依据确定。

### 用业务结果限定建设范围

业务负责人说明目标对象、起止点、质量标准、观察期及记录责任人。客户或接收方参与判断什么产物可以继续使用，管理者确认所需资源和承接能力。范围需要足以观察改善，也要能落实执行、判断、异常接手和维护责任。

例如，诊断一笔签约后未排产的订单，需要同时核对合同启动条件、产品准备、物料和产能，确认是否真的偏离约定。合同、订单、工单和交付批次的关系要能够追踪；插单或外协对其他责任的影响也要保留。资料缺失、尚待确认与已经确认未完成分别表达，再判断本轮补什么记录、连接、分析或行动条件。

<a id="section-2-2"></a>
## 2.2 按价值、条件与依赖组合建设

### 分别判断值得做与能做好

业务负责人先明确一项改造怎样改善客户价值、交付或资源使用，再由建造者、执行者和判断者用真实样本检验工具与服务能否可靠完成。能够生成一份产物，还需要接收者认可其质量并愿意采用。

| 业务判断与当前条件 | 已有可靠交付依据 | 能力不足或尚未验证 |
| --- | --- | --- |
| 值得改进 | 比较完整投入和依赖，列入优先候选。 | 补条件或缩小范围验证，保留现有承接。 |
| 当前不值得采用该做法 | 继续现有安排，说明业务取舍。 | 暂缓投入，条件改变后复核。 |

企业可以保留有效的规则程序、专业软件和人工专业工作。某模块本轮不增加服务，也是按价值与条件作出的具体选择。

### 把有依赖的动作组合成可运行范围

核实每项动作需要的资料、权限、规则、接口、上游产物与接收能力。共享的采集、接口和培训统一安排，有先后依赖的按顺序建设，互不依赖的可以并行。系统数量或企业规模不能替代这项判断。

为处理排产变更，可以在同一范围内补齐关键状态、关联合同和工单、约定跨职能接手，并试验约束解释和获准执行。数据和专业工具已经可靠的部分直接复用，缺少的部分由相应建设任务补齐。基础建设与服务试验共同进入预算和验收。

[上海消费品门店](../下册-案例汇编/F-批发与零售业/F10-上海消费品门店AI对账.md#c-10-f01)据实施者自述，在多个候选任务中先选择较容易观察人工投入与差异的对账，以个位数门店试点。其节时记录仍需与差异处理及实际到账相接，才能判断完整收益。选择容易核对的范围，有利于更快知道后续该如何调整。

<a id="section-2-3"></a>
## 2.3 完成建设、集成与真实运行

### 确定建设方式与交付物

逐项比较存量复用、采购配置、定制开发和服务接入。复用时核对接口、版本和维护条件，采购时用本轮真实业务验证适配，开发时把业务规则与验收样本交给建造者。智力服务可以协助整理需求、编写程序、适配工具和准备测试，建造责任还包括专业核验、实际采用及持续维护。

| 建设工作 | 需要交付什么 | 谁确认可继续 |
| --- | --- | --- |
| 数据、模型与业务规则 | 对象关系、有效来源与版本、适用模型和规则及更新安排。 | 业务及专业负责人确认准确性和用途。 |
| 应用、工具与连接 | 配置或代码、接口与调用约定、权限、异常处理及维护资料。 | 使用方和维护方用真实样本联调。 |
| 设备、网络与现场条件 | 对应模块所需的采集、部署、专业验证和现场试运行。 | 相应专业人员核验功能及运行条件。 |
| 智力服务任务 | 目标、输入、工具权限、产物、接收标准、期限及异常接手。 | 判断者检查质量，接收者确认可以采用。 |
| 交付与维护 | 培训、操作方法、版本、维护人、未完成事项和恢复安排。 | 业务使用方及维护方完成接手。 |

先联调查询、计算、模型调用和写回，再进入选定范围的真实任务。测试保留正常输入、缺失、冲突、版本变化、工具失败与超出权限等情况。仿真、优化和控制按专业要求验证，服务生成的说明与专业工具结果分别检查。

### 把五类职责落实到实际任务

建造者把方法、资料、连接和工具维护成可用能力；执行者按当前依据和权限完成任务；判断者核实事实、专业质量及适用性，决定采用、补证、退回或升级；管理者处理资源冲突和跨岗位依赖；决策者按授权决定重要投入、承诺与经营取舍。同一人可以兼任，服务和程序按实际能力承接任务。

读取什么、能否写回和可以执行哪些动作，需要细到具体工具与业务范围。资料缺失、条件冲突或执行失败时，任务交出已完成内容、受阻位置和未决项，由约定人员接手。实际运行条件明确后，再按业务需要选择单次、定时或事件触发的执行方式。

### 用实际采用检验交付

工具交付后，让真实使用者完成任务，确认产物被采用还是退回，并留下原因。技术功能正确仍可能增加录入、核验或下游积压，需要查清是方法、资料、工具还是资源问题。

[澳洲乳企](../下册-案例汇编/C-制造业/C11-澳洲乳企海外动销分析.md#c-24-f01)据实施者自述，先在一条产品线运行，要求数字能追源、结论进入周会，跑通后再向其他区域扩展。原系统、AI抽取与人工确认各有分工。周会采用之后，还需继续核对预算决定与业务结果。

<a id="section-2-4"></a>
## 2.4 核算完整投入，分层验收结果

### 把价格优势落实到合格交付成本

智力服务能让部分需求整理、开发和测试以较低的调用支出反复开展。经济性需要落实到真实产物：在相同范围、质量和数量下，建设与运行的总投入是否下降；新增的业务能力又能否被有效采用。

一次性投入包括资料整理、方法验证、开发配置、设备及网络、系统连接、培训和权限准备。持续投入包括执行、调用、外部服务、人工判断、交接、返工、异常处理和维护。失败尝试与修复保留，共用投入归集一次。人工工时、模型用量和现金支出分别记录，再依据实际成本和计费规则核算。

本轮预算覆盖计划发生的建设与运行支出，未来可能复用的建设仍计入当期现金需求。比较期间的经济性时，建设分摊使用明确的期间和规则，不再重复计入完整支出。数量不同时，比较相关投入除以合格交付数量所得的单位成本，同时保留规模、任务难度和条件差异。

[温州连锁烘焙企业](../下册-案例汇编/F-批发与零售业/F11-温州连锁烘焙企业AI经营管理.md#s-31-f02)的经营者称，会前填报与口径检查增加，老板制作的原型由开发人员继续完善和兜底。会议准备前移和工具维护都属于完整投入，减少会中时间需要放回同一范围比较。

### 分开验建设、运行、采用与经营结果

| 验收范围 | 检查什么 | 记录怎样支持判断 |
| --- | --- | --- |
| 建设与集成 | 数据和模型适用，功能、接口、权限、专业计算和异常接管符合要求。 | 交付版本、样本、联调、专业核验及现场试运行。 |
| 任务与采用 | 产物合格，接收者确实使用，变化进入后续工作。 | 合格、退回、采用、返工、等待及执行回执。 |
| 业务结果 | 原定交付、质量、库存、资金、客户体验等目标发生什么变化。 | 固定对象、范围、质量、观察期与截止日，保留未结束事项。 |
| 服务贡献 | 在可比基础条件下，服务具体改变什么，增加了哪些投入。 | 同类任务比较或分步接入，记录其他同期变化及归因范围。 |

同时补建基础模块时，项目整体改善与新增服务贡献分别判断。参考架构、官方目标和其他企业成绩不代替本企业基线。没有可比依据时，保留观察与机制分析，服务的净贡献继续验证。

节时、总周期、成本替代、覆盖范围和承接容量分别表达，再看它们是否进入有需求且能兑现的业务。释放员工时间不等于工资现金支出已经减少，销售额、毛利与净利润也使用各自依据。

分析任务还要追踪原因假设是否核实、行动为何被采用或退回、实际动作是否发生及结果是否符合预期。反馈据此改变资料、规则、模型或分工，后续相近任务再验证变化是否有效。记录反馈、人工维护与模型适应性调整按实际发生分别说明。

<a id="section-2-5"></a>
## 2.5 决定扩展、调整或停止

可靠交付、实际采用且投入合理的范围可以保留或扩大。扩展到其他客户、门店、产品线或任务时，重新核对输入、规则、连接、权限和质量条件，确认判断与接收能力足以承接新增数量，并安排维护、预算和复核时间。

采用不足时，先检查是否增加录入、产物不适用、规则不清或指导不足。原因能够定位和修正的，由建造者、使用方及管理者落实改进，再按可比条件检验。持续没有实际使用，核验返工抵消改善，关键条件无法取得或异常无人接手的范围，应减少或停止投入。

[消防维保企业](../下册-案例汇编/M-科学研究与技术服务业/M02-消防维保企业数字化项目取舍.md#c-13-f01)据实施者自述，在确认监管系统没有开放接口后，采用既有工具和小模块，叫停一笔约十万元的计划采购。其局部数字化和采购取舍本身就有价值，AI辅助月检描述仍属于方向。数字化案例可以支持建设选择，不需要补写成已实现的AI成果。

停止时交回未完成任务和客户责任，安排业务接回，保留可复用产物与原因记录，停用失效能力。决策者按授权决定投入，下一轮从新的证据和条件继续选择。
