# 附录A 行业方案选用与建设验收工作表

一芥智能研究院｜《企业数智化转型研究报告》中册｜初稿 v0.3｜2026年10月18日

[中册目录](README.md) · [引言](00-导读.md) · [企业实施方法](../上册-研究报告/08-实施建议-从改造机会到可验证行动.md)

以下工作表用于将行业参考架构和模块对应到本企业的选用、建设与验收。填写方法沿用上册第八章的现状、目标、蓝图与计划，再记录建设、运行和验收。依据来自本企业的真实业务和条件，行业方案提供的参考能力、企业实际基线、基础补建与服务增补分别记录。资料不足时，明确待核实对象和责任人。

## 一、摸清现状：行业方案与企业实际能力对照

| 栏目 | 应记录的内容 | 核对办法 |
| --- | --- | --- |
| 参考文件与应用模块 | 发布或编制者、版本、架构图、模块名称及编号、PDF页码和适用范围。 | 回查原文，确认行业、企业类型和业务边界。 |
| 实际业务 | 从输入到交付的动作、产物、接收者、共享资源及外部协作方。 | 选真实任务，分别向执行者和接收者取得记录。 |
| 现有能力 | 设备、软件、数据、专业模型、工具、网络和人员；实际可用和采用情况。 | 检查正确输入、实际运行、专业结果及后续使用。 |
| 连接与维护 | 对象标识、版本、读取写回、状态传递、异常接手和更新责任。 | 追踪一次变更，确认相关系统及岗位怎样继续。 |
| 业务差距 | 受阻动作、质量或交付影响、发生条件与证据；原因假设及待确认项。 | 核对事实、时间顺序、例外和反例。 |
| 当前投入与结果 | 同范围的准备、执行、核验、交接、返工和维护，及交付、质量或经营表现。 | 固定对象、口径、期间和截止日，保留未结束事项。 |

现状产物包括行业应用模块与企业实际能力对照、问题清单及企业基线。企业已建模块也要检查采用，表格和人工处理也要按其实际作用记录。

## 二、确认目标：结果、范围与约束

| 栏目 | 需要确定什么 | 谁确认 |
| --- | --- | --- |
| 业务结果 | 本轮希望改善的设计、生产、服务、质量、交付、资源周转或经营表现。 | 业务负责人说明价值，接收者确认产物用途。 |
| 对象与范围 | 覆盖的产品、工况、产线、客户、项目或任务，起止点及外部责任。 | 业务与专业负责人确认适用边界。 |
| 质量与比较 | 基线、质量要求、统计口径、合格数量、观察期、截止日及记录人。 | 判断者与验收人共同确认。 |
| 资源与约束 | 预算、人员、设备、专业条件、访问授权、业务连续性及合作方条件。 | 相应负责人核实可取得条件。 |
| 本轮取舍 | 哪些目标优先，哪些依赖需要先满足，哪些范围暂缓。 | 决策者按业务价值和资源决定。 |

目标说明应能连接现状差距和后续验收。行业方案的参考目标用于认识建设方向，本企业的承诺由实际条件和授权确认。

## 三、画蓝图：建成后的业务和能力关系

| 蓝图内容 | 需要画清或写清什么 | 应形成的设计产物 |
| --- | --- | --- |
| 业务与应用模块 | 未来业务怎样运行，所选应用模块怎样配合，各岗位形成和接收什么。 | 目标业务图、模块及产物关系、企业适用范围。 |
| 数据、知识与专业模型 | 对象及版本，资料来源、有效规则、适用模型、维护位置与责任。 | 对象与数据模型、知识引用关系、专业验证要求。 |
| 系统、设备与连接 | 企业现有和本轮新建的系统设备，客户供应商及岗位之间如何交换信息、共享资源。 | 系统与设备关系图、接口及字段映射、状态传递和权限安排。 |
| 工具与服务任务 | 所选专业工具、规则程序和工业AI承担什么，服务参与何处及其输入、产物和权限。 | 工具与任务规格、执行触发、判断及异常接手位置。 |
| 使用、管理与结果 | 谁使用、谁维护、谁核验、谁协调资源、谁决定重要投入与承诺。 | 运行职责、采用方式、看板与结果回查、维护及恢复安排。 |

在蓝图上标明**保留、复用、补建、改造、服务增补、暂缓**的内容，并关联本轮目标及相应应用模块。总体关系图配合接口、对象和任务说明，专业功能继续按相应要求设计。

选用A11场景图谱时，沿数据、知识模型、工具软件、人才技能逐项核对；采用其他方案时保留参考文件的要素分组。数字表达与处理、连接协同、分析及获准行动共同进入目标状态，建设依赖另在计划中落实。

## 四、制定计划：将蓝图拆成可交付工作包

| 计划栏目 | 每个工作包需要明确什么 |
| --- | --- |
| 目标与应用模块 | 支持哪项结果，对应蓝图哪一部分、哪项应用模块或服务增补。 |
| 建设内容与方式 | 复用、采购配置、自建、定制或服务接入，必要的数据、设备、网络和专业工作。 |
| 交付物 | 可以验收的系统功能、数据或模型、接口、工具、配置、测试及维护资料。 |
| 依赖与进入条件 | 哪些输入、资源、批准和前序产物必须具备，哪些工作能够并行。 |
| 责任与接收 | 建设负责人、专业判断者、使用方、维护方、验收人及合作方。 |
| 资源和预算 | 人员、采购、开发、现场、专业验证、调用、培训和维护的预计投入及依据。 |
| 节点与验收 | 计划完成点、验收样本和标准、试运行范围，以及进入下一步的条件。 |
| 采用与持续运行 | 培训、真实使用、失败接回、恢复、维护和下一次复核安排。 |

共享的数据整理、接口和培训统一安排投入；各工作包按实际依赖排定。预算覆盖必要的建设与运行现金需求，经济性比较另说明分摊期间和规则。

例如，围绕排产变更，可以分别安排有效产品与工艺资料、计划及现场连接、约束检查与解释任务、真实业务试运行等工作包。每个包都对应蓝图及业务目标，选用的排程工具和专业核验同时落实；实际范围、次序和节点由企业条件确认。

## 五、一项智力服务任务的约定

| 约定事项 | 应写清什么 |
| --- | --- |
| 目标与期限 | 处理哪个对象，为何处理，何时交付。 |
| 输入与依据 | 当前要求、原始记录、有效版本、业务规则、适用模型和约束。 |
| 工具与权限 | 可检索、计算、调用和执行什么，哪些动作须先批准。 |
| 产物与接收者 | 交付位置、来源及未决项，下一岗位怎样继续使用。 |
| 质量与验收 | 样本、可核查标准、验收人及采用、退回的记录。 |
| 异常接手 | 资料缺失、冲突、失败或超出授权时交回什么，由谁继续。 |
| 运行与维护 | 单次、定时或按条件发起，执行记录、版本、维护和停止安排。 |

建设任务交出可运行工具和验证记录，业务任务交出获准范围内的处理结果。AI辅助开发的功能与运行时调用服务分别验收，人的判断、协调及经营决定按实际职责保留。

## 六、建设、联调与交付

| 环节 | 形成什么记录 | 进入下一步的条件 |
| --- | --- | --- |
| 配置与开发 | 配置或代码、对象模型、工具及接口、专业资料和维护说明。 | 复用功能与本轮新建内容均可在规定环境中验证。 |
| 集成与专业验证 | 查询、计算或模型调用、状态传递、写回、现场部署及专业核验。 | 真实输入正确传递，功能满足用途，异常可接手。 |
| 真实业务试运行 | 合格与退回、实际采用、等待返工和执行结果。 | 产物进入后续安排，主要受阻问题能够定位处理。 |
| 交付与维护 | 版本、培训、操作资料、责任、未完成事项、恢复和复核安排。 | 使用者与维护者接手，后续资源和责任明确。 |

保留正常、边界、缺失、冲突、版本变化、工具失败及超出授权等样本。运行事实变化时，说明对已确认目标、蓝图和计划的影响，由相应负责人决定调整。

## 七、验收及完整投入比较

| 范围 | 企业实际基线 | 本轮记录与判断 |
| --- | --- | --- |
| 数字化建设 | 企业现有可用功能、设备、数据与专业模型及采用情况。 | 必要能力是否建成，专业结果是否可靠，所选模块是否满足本轮用途。 |
| 集成与服务任务 | 企业现有连接、资料准备、判断和接手方式。 | 对象及版本准确，查询写回及授权正确，产物合格、异常可接手。 |
| 采用与业务结果 | 实施前的合格率、总周期、等待、返工及相关业务表现。 | 产物实际使用及执行，交付、质量、资源或经营结果的同口径变化。 |
| 服务新增贡献 | 未接入服务时的实际做法或可比任务。 | 服务改变的具体动作、响应、覆盖、投入和结果，注明其他同期变化。 |
| 完整投入 | 实施前同类工作的资料准备、建设、执行、专业判断、交接和维护投入。 | 本轮资料、方法、开发、设备网络、集成、调用、判断、返工、培训及维护。 |

提前固定对象、范围、质量、样本、合格数量、观察期、截止日及验收责任。项目总体变化、基础补建价值和服务增量分别记录，参考图谱中的评级和其他企业成绩保留各自范围。

一次性建设和持续运行分列，共用投入归集一次。现金需求与比较期间的分摊分别表达，同一比较不重复计入完整建设支出及其分摊。同等范围、质量和数量比较总投入，数量变化时比较单位合格交付成本；新增覆盖另看用途和价值。

## 八、反馈与下一步决定

复盘保留目标与基线、实际产物和采用、完整投入、原因与行动结果、异常及未完成责任。判断继续、扩展、调整或停止，说明范围、依据、负责人和复核时间。

反馈可以改变资料、方法、工具或分工，也可以改变本轮目标、企业蓝图和实施计划。扩展前核对新范围的专业条件、输入、规则、工具、权限及承接能力；停止时安排未完成业务接回、可复用产物保存与失效能力停用。后续相近任务的可比结果用于检查改善能否保持。
