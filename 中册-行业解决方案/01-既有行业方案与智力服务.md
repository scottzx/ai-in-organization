# 第一章　在既有行业方案中增加智力服务

一芥智能研究院｜《企业数智化转型研究报告》中册｜初稿 v0.1｜2026年10月18日

[中册目录](README.md) · [导读](00-导读.md) · [下一章](02-建设实施与验收.md)

企业选择方案，先要看它能否支持自己的产品、生产、服务和经营。行业指南已经把许多业务拆成模块与场景，给出对应的数据、模型、软件、设备及人员要求。沿这些关系核实企业的实际条件，再把合适的工作交给智力服务，才能让新增能力进入原有业务。

<a id="section-1-1"></a>
## 1.1 从原架构找到适用的模块

选择行业文件时，先核对适用范围、版本、编制机构、架构图和场景页码。实施方案可能主要列建设方向，融合指南可能包含总体架构与实施架构，场景图谱则可能进一步列出具体工具和知识模型。多份文件共同使用时，说明各自承担什么作用和模块之间的对应关系。

A11《场景化、图谱化推进重点行业数字化转型的参考指引（2025版）》PDF第3—6页，以产业链主线、业务活动、场景和数字化要素组织行业图谱。其业务活动包括研发设计、生产制造、运维服务、经营管理、供应链管理；四类要素包括数据、知识模型、工具软件、人才技能。知识模型既包含信息、机理、规则模型，也包含智能模型。这些内容为模块建设提供了具体基础，原文见[参考指引第3页起](https://www.miit.gov.cn/cms_files/filemanager/1226211233/attach/20259/60b964bacb4e4c6886ad27349060bb36.pdf#page=3)。

沿图谱判断本企业处在哪个产业链环节、开展哪些业务，再选择需要使用的模块。整机厂的装配排产、零部件厂的工序与设备安排、服务组织的维修与备件，不能只因属于同一行业就采用相同范围。模块目录保留原名与编号，对合并、裁剪和新增的内容说明对应关系。

<a id="section-1-2"></a>
## 1.2 从实际工作确定本轮差距

参考架构列出的是可以建设和使用的能力。企业是否已经具备这些能力，需要通过真实业务核对：当前使用哪些系统和设备，资料与模型是否有效，实际产物交给谁，哪些工作仍依靠补问、重录和临时判断。

例如，按图谱已有排产模块的企业，还要检查订单需求、工艺、物料、设备与人员容量能否共同用于排程。计划已经发布而现场没有采用，与排程依据缺失、软件功能不足或资源冲突，是不同问题。分析围绕高标准动作和受阻工作展开，先找证据，再确定目标。

基础较薄时，选择一笔订单或一类任务作为观察范围，仍要保留它与其他订单、共享资源、客户承诺和供应商条件的关系。一个业务对象可以帮助追踪，整项建设则按实际对象关系与责任展开。规模和系统数量只说明部分条件，不能直接代替就绪度诊断。

<a id="section-1-3"></a>
## 1.3 让三化共同支持同一业务目标

数字化建设要形成可处理的数据与模型，按模块用于记录、计算、仿真或控制。除了来源、时间和版本，还要检查数据和模型能否支持其实际用途。设计仿真、设备数控或工艺处理等已有能力，应当保留相应的专业验证。

网络化检查这些对象与资源怎样连接和协同。设备与系统、市场与研发、计划与执行、企业与客户供应商之间，需要有适用的连接方式、共同对象、访问权限和工作接手。记录被复制、消息被发送之后，还要确认接收者可以继续工作，变化进入了实际安排。

智能化检查系统具体承担什么感知、识别、预测、推理、优化、决策执行及适应性调整。专业软件、工业算法和智力服务按任务组合，人的专业判断和重要经营取舍按授权落实。人工看完报表后独立作出的分析，与系统可靠完成的工作分别记录。

三化在同一目标下按依赖建设。例如，为缩短设计变更处理时间，可以同时补齐有效版本和参数表达、关联工艺与采购影响、调用工具比较方案，再让获准变化进入后续执行。现有条件具备的部分直接使用，有缺口的部分明确建设任务，按真实业务逐步扩大。

<a id="section-1-4"></a>
## 1.4 沿原模块安排三类服务任务

**协助建造。** 业务人员提出目的、规则与使用要求，服务参与需求整理、数据结构、代码、接口、测试和文档。建造者核验专业条件和实现，实际使用者检验产物能否进入业务，再安排维护。由AI辅助开发的普通程序可以稳定重复执行，运行时是否需要模型另按任务选择。

**协调传递。** 服务从获准记录中组织共同背景，比对不同表达，提示缺项和冲突，准备可接手的材料并跟踪结果。固定标识匹配、金额计算与状态传递由适用程序处理，需要理解语境的工作按实际能力交给服务。重要业务状态仍由原系统及责任岗位维护，汇总与解释指向有效来源。

**分析推理。** 服务结合数据、规则、知识和专业工具，识别偏差、比较原因假设与行动选项，说明约束和待验证项。服务可以在明确权限内调用工具和执行动作，重要承诺与经营取舍由有权者决定。执行结果回到原问题复核，区分分析错误、行动未发生和行动后无效。

同一模块可以组合三类作用，也可以只增加其中一项。原有规则程序、优化算法或专业软件已经能可靠完成的工作继续使用。原方案已有的视觉、预测、控制或大模型能力，按原有内容保留，新增服务的价值从具体变化中检验。

<a id="section-1-5"></a>
## 1.5 把增强内容写成可以建设的方案

一项模块方案需要同时写清业务做法和技术参与。先说明当前动作、希望达到的结果、受阻原因与改进举措，再落实工具、模型和服务的支持条件。方案设计到可运行产物，运行任务再接到接收者和业务结果。

| 方案内容 | 建设时要确定的事项 | 交付或验收的依据 |
| --- | --- | --- |
| 原模块与目标 | 原文名称、页码、适用企业，企业实际差距及本轮目标。 | 原架构对照、现状记录、目标及观察范围。 |
| 功能与工作 | 原功能保留或补建什么，新增服务承接什么，产物供谁使用。 | 可运行功能、任务产物、接收标准及未决项。 |
| 条件与连接 | 有效数据、知识模型、专业工具、设备与网络条件，以及查询、写回和执行权限。 | 版本、接口、配置、真实样本测试和专业核验。 |
| 实施与责任 | 复用、采购或开发，集成联调、试运行、培训、维护及异常接手。 | 建设工作、责任、依赖、交付记录及维护交接。 |
| 价值与改进 | 企业实际基线、投入和业务结果，反馈怎样改变后续工作。 | 采用、质量、总周期、完整投入及后续可比结果。 |

[3C外贸企业](../下册-案例汇编/F-批发与零售业/F09-3C外贸企业AI自建业务系统.md#s-07-f01)将固定产品资料和规则用于单据生成，AI参与建设，已有系统负责日常输出。把建设方式与运行方式分清，企业才能正确估算开发、调用和维护的投入，也能选择适当的验收方式。

资料分布在多个系统时，可以采用获准查询、共享索引或接口关联。所需知识的发现、引用和维护参照[上册附录D](../上册-研究报告/附录D-知识网络建设细节.md)，按本轮任务补齐条件。统一发现和使用资料，与强制搬迁全部原文是不同建设选择。

<a id="section-1-6"></a>
## 1.6 保留原架构、案例和增补的对应关系

各行业原图谱在章内保留标题、来源与PDF页码，并提供原PDF入口。原模块的关系和名称用于读者回查，新增服务的参与内容在正文或增补图中另作说明。原图中的评级和价值标签按原发布范围理解，不替代某家企业的现状或新增服务实测结果。

企业实践就近支持相应举措，并在下册独立维护。数字化和自动化案例可以说明可靠记录、专业系统、设备及协作怎样形成基础；没有披露AI的材料仍有研究价值。原文事实、一芥的机制分析和待实施的增强方案分别表达，案例的局部成果不拼成已经运行的整套方案。

本章采用的原方案组织方式来自A11参考指引，模块选择、服务任务和建设要求的具体应用为本报告整理。完整资料入口见[行业资料库](../索引/工信部行业数字化转型资料汇总.md)，企业过程见下册，实施与验收方法进入[第二章](02-建设实施与验收.md)。
